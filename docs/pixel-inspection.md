# 픽셀 관찰과 ROOM 1-2 체험

## 진행과 완료 경계

Core/Learning의 단계는 `Tutorial → ScreenLab → ConvolutionLab → FeatureMap → ModelDesign`이다. ROOM 1-2의 `CNNConvolutionLab`에서는 5×5 RGB 입력에 필터를 배치하고 아홉 출력 위치를 계산한다. 결과를 확인한 뒤 ROOM 2의 `CNNFeatureMapLab`으로 이어진다.

출력값을 기록할 때마다 진행률을 갱신하며 아홉 칸을 모두 기록하면 95%에 도달한다. **결과 확인**을 누르면 출력값의 의미를 보여 주는 마무리 장면을 재생한다. **체험 마치기**를 누르면 `CNNConvolutionLabManager`가 `Progress=1`과 `CanExit=true`를 알린다. 누적 진행률은 `LearningProgress`가 체험별 최댓값으로 기록한다.

## 독립적인 관찰과 합성곱 입력

`CNNScreenLab`은 숫자 2 색점판에서 선택한 3×3 RGB 0~255 관찰을 담당한다. 첫 화면에는 원본 텍스처를 표시한다. `PixelImageFactory`는 같은 원본을 128×72로 축소하고 5×5 블러를 적용한 뒤 32×18로 샘플링해 픽셀 관찰에 사용한다. `PixelImageData.CapturePatch`가 만든 `PixelPatchData`는 관찰 내부에서만 사용하며 `Scripts/CNNScreenLab/PixelPatchData.cs`에 둔다. 외부로 선택 데이터를 공개하거나 전달하지 않는다.

`CNNConvolutionLab`은 `Scripts/CNNConvolutionLab/ConvolutionCalculation.cs`의 `CreateExample()`에 저장된 0~3 값의 고정 5×5 RGB 배열로 시작한다. 순차 입장, 태블릿 직접 이동, 단독 실행 모두 같은 예제를 사용한다. 1-1의 선택 여부나 완료 상태로 입력을 바꾸지 않는다. 계산 결과는 이 배열과 필터로 매번 계산한다.

`FactorySceneLoadController`는 인접 씬을 미리 로드한다. ScreenLab과 ConvolutionLab은 로드 후 각자의 `Start`에서 자체 초기화하며, 공장의 현재 구역이나 실제 입장 여부를 전달받지 않는다. ConvolutionLab은 고정 예제를 준비하고 필터 배치 입력을 기다린다. 공장 내 로드와 단독 실행은 같은 시작 경로를 사용한다. 로드된 상태에서는 구역 이동만으로 체험을 중단하거나 초기화하지 않는다.

`LearningSessionManager`는 구체 체험 Manager를 참조하지 않고 `ILearningExperience`로 단계·진행률·출구 허용 상태를 조회하고 변경 이벤트를 구독한다. 언로드 전에는 같은 인터페이스의 `EndSession`으로 정리를 요청한다. 공장 셔터의 개방 조건은 [Factory Environment](factory-environment.md)의 셔터 동작을 따른다.

두 체험의 UI 버튼은 공용 `XRPlayerRig`에 구성한 EventSystem·XRUIInputModule을 사용한다. `ScreenLabUIController`와 `CNNConvolutionLabManager`는 입력 환경을 생성하거나 해제하지 않으며, 버튼의 기존 On Click 연결로 각 체험의 요청을 처리한다. 체험 종료·언로드 시 공용 입력 환경은 유지된다. ScreenLab 단독 실행은 씬에 배치된 공용 리그를 사용하고, 자체 리그가 없는 ConvolutionLab의 XR 조작은 공장에 로드된 공용 리그를 사용한다.

## ROOM #1-1 픽셀 큐브 미리보기

`Floating image board/Low resolution image`의 `PixelGridData`는 색점판 원본을 칸별 면적 평균으로 48×27 RGB 배열에 저장한다. `GetColor(x, y)`와 `TryWorldToGrid`는 왼쪽 아래 칸을 (0, 0)으로 사용한다. 원본 텍스처의 Read/Write가 필요하다.

같은 오브젝트의 `PixelShatter`는 단위 Cube 메시와 `PixelGridCubes` 재질을 사용한다. 기본 상태는 숨김이다. Inspector 컴포넌트 메뉴의 `ShowGrid`와 `HideGrid`로 전환한다. 표시 중에만 원본 렌더러를 가리고, 숨길 때 기존 상태로 복구한다. 큐브는 최대 250개씩 인스턴싱해 그린다. Play 중에는 돋보기의 기존 `SelectionChanged`가 처음으로 유효한 3×3 선택을 알릴 때 0.3초 이미지 페이드와 1초 큐브 전개를 시작한다. 기존 선택 중심을 48×27 좌표로 변환해 해당 3×3을 강조한다. RGB 확대도 같은 중심의 9개 색을 `PixelGridData.GetColor()`로 읽어 채널 표시와 숫자판에 전달한다. 실시간 갱신 경로에서는 RGB 값을 Console에 출력하지 않는다. 다시 놓으면 강조 위치만 갱신한다. 같은 위치에서 1초 관찰한 뒤 RGB 펼침이 시작되면 큐브 연출을 중단하고 원본 이미지를 복구한다. ‘처음으로’도 연출을 중단하고 원본 렌더러 상태를 복구한다.

## ROOM #1-1 돋보기 전시대

`CNNScreenLab` 씬의 `CNN Screen Lab/MagnifierPedestal` Transform이 전시대 위치를 정한다. 받침대 윗면은 지름 0.56m, 바닥 기준 높이 1.0m에 있고 `MagnifierDock`은 윗면에서 0.175m 위에 있다. 시작하거나 선택을 초기화하면 돋보기는 이 기준점으로 돌아온다. 전시대에는 충돌 영역을 두지 않으며 기존 파란 바닥 표시는 비활성 상태로 보존한다.

전시대 위 돋보기의 `MagnifierIdleFloat`는 초당 30° 회전하고 0.5Hz로 ±3cm 움직인다. 기존 `XRGrabInteractable.selectEntered`에서 멈추고 ‘처음으로’의 `ScreenLabUIController.ResetRequested`에서 다시 시작한다. 잡힌 상태의 리셋 요청은 기존 동작과 같이 무시한다.

돋보기에는 짙은 금속 테두리와 반투명 렌즈가 있다. 같은 잡기 이벤트에서 `MagnifierPickupFX`가 렌즈 가장자리의 하늘색 띠를 먼저 반짝인다. 0.14초 뒤에 빛기둥이 0.4초에 걸쳐 꺼지기 시작하고, 전시대 링은 기존 밝기의 22%로 낮아진다. 돋보기 위치에서 최대 0.5초 동안 하늘색 파티클을 표시한다. Inspector의 `pickupClip`에 클립을 연결하면 공간 효과음을 재생한다. ‘처음으로’는 조명을 복구하고 다음 첫 잡기 연출을 준비한다.

## 공중 합성곱 구성

받침대 없이 입력·계산판·출력판을 공중에 띄우고, 단계마다 필요한 묶음만 가운데에 보여 준다. 공장 콘텐츠 기준점은 `(-28.55, -0.3, -2.0)`, Y 회전은 -90°, 콘텐츠 배율은 1.2, 내부 Workbench 배율은 1.15다. `WorkbenchHologramBackdrop`이 표시판 뒤에 곡면 홀로그램 배경을 그린다.

`ConvolutionWorkbench.prefab`은 다섯 묶음과 일곱 슬롯을 저장한다. 묶음은 기준점을 자식으로 가지며, `FocusLayoutController`가 장면에 맞는 슬롯으로 묶음을 옮긴다. 슬롯 위치는 프리팹의 `Focus slots` 아래에서 조정한다.

| 묶음 | 포함 기준점 | 사용하는 슬롯 |
| --- | --- | --- |
| `Input group` | 입력, 필터 시작 위치·첫 목표, 손잡이 안내 | `Input center slot`, `Input side slot` |
| `Products group` | 중간 곱 | `Grid center slot`, `Grid side slot` |
| `Output group` | 최종 출력 | `Grid center slot`, `Grid side slot` |
| `Equation group` | 곱셈식·합계·합산식 | `Equation center slot`, `Equation side slot` |
| `Meaning group` | 마무리 장면의 그림·막대 지도·다음 단계 상자 | `Meaning slot` |

| 장면 (`FocusLayout`) | 보이는 묶음 |
| --- | --- |
| `Input` | 입력과 필터(가운데) |
| `InputAndProducts` | 입력과 필터(왼쪽), 중간 곱과 식(오른쪽) |
| `Products` | 중간 곱과 식(가운데) |
| `InputAndOutput` | 입력과 필터(왼쪽), 출력과 식(오른쪽) |
| `Output` | 출력(가운데) |
| `Meaning` | 마무리 장면(가운데) |

장면이 바뀌면 필요 없는 묶음은 줄어들며 사라지고, 남는 묶음은 새 슬롯으로 이동한 뒤, 새 묶음이 슬롯에서 커지며 나타난다. 필터는 `Input group` 아래에 두어 입력과 함께 이동하고 숨겨진다. 중간 곱과 최종 출력은 같은 슬롯을 쓰며 동시에 표시하지 않는다.

| 공간 요소 | 현재 표시 |
| --- | --- |
| 입력 | 5×5 RGB 세 층. 뒤 채널은 앞 채널에 비해 로컬 X -0.34, Y +0.06, Z +0.30씩 어긋난다. |
| 비활성 채널 | 외곽 프레임·측면 채널 라벨·현재 3×3 영역은 남기고, 상단 제목과 숫자 타일은 숨긴다. 비활성 내부 격자선은 만들지 않아 뒤 채널 숫자를 가로지르지 않는다. |
| 필터 | 손잡이 하나와 연결된 RGB 세 프레임. 활성 채널의 가중치 숫자만 표시한다. 세 프레임은 하나의 잡기 대상으로 함께 움직인다. 시작 위치는 입력 오른쪽 앞이다. |
| 중간 계산 | 별도 3×3 격자에 현재 채널의 아홉 곱을 표시한다. 최종 출력과 셀을 공유하지 않는다. |
| 최종 출력 | 전용 3×3 격자. 계산 위치에 해당하는 출력만 기록하고 중간 곱으로 덮어쓰지 않는다. |
| 연산식 | 곱셈식과 채널·RGB 합산식은 격자 아래에 표시한다. 숫자 사본만 이동하고 원본 입력은 보존한다. 내용이 없는 식 판은 숨긴다. |
| 자막 | 초점 아래의 자막 막대 한 줄에 현재 단계의 짧은 안내를 표시한다. 자세한 설명은 안내 음성이 담당한다. |
| 조작 | 오른쪽 버튼판에 주 동작·다시 보기·일시정지·처음으로 버튼만 배치한다. |

배치 단계의 손잡이 안내는 필터 근처에 표시한다. `PixelCalculationUI.prefab`에 자막 막대와 버튼판의 배치가 저장되어 있다. 버튼은 공용 `WorldUIButton`의 중첩 인스턴스다.

오른쪽의 주 동작 위치에 필터 자동 배치, 다음 단계, 한 칸 자동 이동, 결과 확인, 체험 마치기를 단계에 따라 표시한다. 현재 사용할 수 있는 주 동작 버튼의 금색 테두리는 밝아졌다 어두워진다. 일시정지 중에는 체험 재개 버튼을 강조한다. 다시 보기는 별도 줄에 있다. 재생 중에는 다음·다시 보기 버튼을 숨긴다. 일시정지는 연출 시간·안내 음성·필터 입력·퀴즈·다음·다시 보기·자동 배치를 멈춘다. 처음으로는 현재 코루틴과 입력, 음성을 정리하고 첫 배치로 돌아간다.

## 안내 음성

`LessonNarrationController`가 단계별 음성을 한 번에 한 줄씩 재생한다. 음성 파일은 `client/Assets/Audio/CNNConvolutionLab/ConvolutionNarration_<Cue>.wav`이며, 씬의 `Lesson narration` 오브젝트가 `NarrationCue` 순서로 참조한다. 새 음성을 요청하면 재생 중인 음성은 멈춘다.

AudioSource는 초점 중앙에 둔 3D 음원이며 6m까지 원래 크기, 14m에서 들리지 않도록 선형으로 줄어든다. 씬은 입장 전에 미리 로드되므로, 청자(`Camera.main`)가 9m 밖에 있을 때 요청된 음성은 보류했다가 범위 안으로 들어오면 재생한다. 카메라가 없는 단독 실행에서는 바로 재생한다.

곱하기·합산·출력 기록처럼 설명이 필요한 연출은 해당 음성이 끝날 때까지 다음 연출을 기다린다. 조작을 기다리는 단계의 음성은 진행을 막지 않는다. 음성은 `LessonPlayback`의 배속을 따르지 않는다.

숫자를 읽는 음성은 고정 예제의 첫 위치 값에 맞춰 녹음했다. `ConvolutionCalculation.CreateExample()`의 입력이나 가중치를 바꾸면 ‘값 포함’ 음성을 다시 만든다.

| `NarrationCue` | 재생 시점 | 문구 | 값 포함 |
| --- | --- | --- | --- |
| `PlaceFilter` | 배치 시작 | 합성곱 체험을 시작할게요. 가운데 떠 있는 숫자판이 입력이에요. 빨강, 초록, 파랑, 세 층으로 이루어져 있어요. 오른쪽에 있는 필터의 손잡이를 잡아서, 입력의 왼쪽 위 점선 자리에 놓아 보세요. | |
| `FilterPlaced` | 배치 완료 | 좋아요. 필터가 입력의 왼쪽 위 아홉 칸을 덮었어요. | |
| `MultiplyIntro` | 곱하기 시작 전 | 이제 합성곱을 계산해 볼게요. 필터와 겹친 아홉 칸에서, 같은 자리에 있는 입력값과 필터의 가중치를 하나씩 곱해요. 곱한 값은 오른쪽 계산판의 같은 자리에 들어가요. | |
| `MultiplyFirstCell` | 첫 칸 곱하기 | 먼저 빨강 층의 첫 번째 칸이에요. 입력값 0에 가중치 1을 곱하면 0이에요. | ○ |
| `MultiplyCenterCell` | 가운데 칸 곱하기 | 가운데 칸은 입력값 2에 가중치 1을 곱해서 2가 돼요. | ○ |
| `MultiplyDone` | 아홉 칸 완료 | 아홉 칸을 모두 곱했어요. 가중치가 0인 칸은 곱한 값도 0이 돼요. | |
| `ChannelSum` | R 채널 합 | 이번에는 계산판에 모인 아홉 개의 곱을 모두 더해요. 0이 아닌 값은 2와 1뿐이니까, 빨강 층의 합은 3이에요. | ○ |
| `GreenChannel` | G 채널 계산 | 초록 층도 같은 방법으로 계산해요. 같은 자리끼리 곱하고 모두 더하면, 초록 층의 합은 6이에요. | ○ |
| `BlueChannel` | B 채널 계산 | 파랑 층도 마찬가지예요. 파랑 층의 합도 6이에요. | ○ |
| `RgbSum` | 세 채널 합 모으기 | 마지막으로 세 층의 합을 하나로 더해요. 빨강 3, 초록 6, 파랑 6을 더하면 15예요. | ○ |
| `FirstOutput` | 첫 출력 기록 | 이 15가 출력값 하나예요. 필터가 왼쪽 위에 있었으니까, 출력판의 왼쪽 위 칸, 1행 1열에 들어가요. | ○ |
| `Checkpoint` | 다음·다시 보기 대기 | 다음 버튼을 누르면 이어서 진행해요. 한 번 더 보고 싶으면 다시 보기를 눌러 주세요. | |
| `MoveFilter` | 직접 한 칸 이동 | 이제 필터를 오른쪽으로 한 칸 옮겨 볼게요. 손잡이를 잡고 오른쪽 표시까지 옮긴 다음 놓아 주세요. 필터의 가중치는 바뀌지 않아요. | |

## 계산 규칙

입력 5×5×3, 공간 필터 3×3, 전체 가중치 3×3×3, stride 1, 패딩 없음, 편향 0이다. 세 채널의 연습용 가중치는 모두 `1 0 0 / 0 1 0 / 0 0 1`이다. 입력값과 가중치는 기존 고정 예제를 유지한다. 각 채널의 아홉 곱을 더하고 RGB 채널 합 세 개를 더해 출력 한 칸을 만든다. 짧은 합산식에서는 가중치 0 항을 생략하지만 중간 계산판에는 0인 곱도 표시한다.

필터 왼쪽 위 `(row,column)`은 출력판의 같은 좌표에 대응한다. 필터의 세 층과 입력의 세 영역은 같은 공간 좌표 이동을 공유한다. `ConvolutionCalculation.ForWindow`는 입력 배열을 공유하는 새 읽기 전용 위치 객체를 반환한다. 입력 배열을 변경하거나 외부에 공개하지 않는다.

## 진행 순서

괄호 안은 그 단계의 장면이다.

1. **배치 (`Input`):** R 숫자와 RGB 세 입력 프레임, 오른쪽 앞의 필터를 표시한다. 반투명 필터 이동 미리보기와 점선 목표를 따라 Grip으로 필터를 놓는다. 목표 로컬 반경 0.15 안에서 놓으면 정렬하고, 밖이면 시작 위치로 돌아간다. 자동 배치도 제공한다. 내부 배율을 포함한 현재 반경은 약 0.207m다.
2. **곱하기 (`InputAndProducts`):** 원리 음성이 끝나면 첫 R에서 필터의 아홉 칸을 왼쪽 위부터 행 순서로 상세히 재생한다. 각 칸의 입력값과 가중치를 곱한 뒤 결과를 중간 계산판의 대응 칸으로 하나씩 옮긴다. 첫 칸과 가운데 칸은 값을 읽는 음성이 끝난 뒤 다음 칸으로 넘어간다. 아홉 칸이 채워지면 `다음 · 아홉 곱 더하기` 또는 `다시 보기`를 기다린다.
3. **채널 합 (`Products`):** 입력을 숨기고 중간 계산판만 가운데에 둔다. 아홉 곱의 사본이 계산판 중심에 모이고 R 합이 된다. 원래 곱은 유지한다. `다음 · RGB 합치기` 또는 현재 합산 단계의 `다시 보기`를 기다린다.
4. **RGB와 첫 출력 (`InputAndProducts` → `InputAndOutput`):** 같은 위치에서 G·B의 곱과 채널 합을 음성과 함께 차례로 표시한다. 이어서 계산판 대신 출력판을 띄우고, R·G·B 합 숫자가 각 필터 층에서 합산 지점으로 모인다. 합산 음성이 끝나면 하나의 출력값이 출력판에 기록된다. `다음 · 필터 한 칸 이동` 또는 이 RGB 합산 단계의 `다시 보기`를 기다린다. 재보기는 해당 단계만 재생하며 진행률을 중복 가산하지 않는다.
5. **직접 한 칸 이동 (`Input`):** 손잡이를 다시 잡고 오른쪽 목표로 옮긴다. 손의 이동을 시작점~다음 격자 중심 선분에 투영하므로 높이·깊이는 고정되고 한 칸 범위를 벗어나지 않는다. 목표 로컬 거리 0.07 안에서 놓으면 정렬한다. 미달하면 시작점으로 돌아가 안내한다. `한 칸 자동 이동`은 같은 목표로 이동하며 퀴즈를 건너뛰지 않는다. 잡은 상태에서 일시정지하면 잡기를 해제하고 이동 시작점으로 돌아간다.
6. **위치 퀴즈 (`Output`):** 출력판만 가운데에 두고 빈칸 8개 중 하나를 XR 레이로 선택한다. 순환 강조는 약 0.30초 간격이다. 오답이면 선택한 행·열과 “오른쪽 한 칸” 힌트를 자막과 음성으로 알리고 재선택을 기다린다. 정답인 1행 2열을 선택하면 입력을 닫고 계산을 진행한다.
7. **자동 계산 (`InputAndOutput`):** 나머지 위치에서 이동 → R → G → B → RGB 합 → 출력 기록을 진행한다. 중간 계산판은 표시하지 않고 채널 합산식만 출력판 아래에 보인다. 왼쪽부터 오른쪽, 위에서 아래의 행 순서다. 둘째 행의 시작으로 이동할 때 음성으로 알린다. 자동 계산은 첫 상세 연출에 적용하는 공통 배속에 1.5배를 더 곱하며 일시정지할 수 있다.
8. **결과 확인 (`Output`):** 아홉 출력에서 95%가 되고 완성된 출력판만 남긴 채 `결과 확인`을 기다린다.
9. **출력값의 의미 (`Meaning`):** 조작 없이 자동으로 진행하는 마무리 장면이다. 글자 N이 그려진 7×7 그림 위를 대각선 필터가 훑고, 기울어진 5×5 지도에서 칸마다 막대가 솟는다. 필터와 닮은 획이 있는 자리일수록 막대가 높고 밝다. 세로 필터로 한 번 더 훑어 두 번째 지도를 만든 뒤, 두 지도가 `다음 단계` 상자로 들어가고 상자에 `N`이 표시된다. 이어서 `체험 마치기` 버튼을 표시하며, 눌러야 100% 및 출구 허용 상태가 된다. 음성 세 줄을 모두 들으면 약 30초다.

출력 순서는 `(1,1)→(1,2)→(1,3)→(2,1)→(2,2)→(2,3)→(3,1)→(3,2)→(3,3)`이다. `LessonPlayback`의 공통 배속은 1.5배다. 자동 이동은 일반 한 칸이 약 0.13초, 다음 행 시작으로 돌아갈 때 약 0.29초다. 장면 전환은 사라지는 구간 약 0.27초, 나타나는 구간 약 0.23초다. 다음·다시 보기, 배치, 직접 이동, 퀴즈, 결과 확인과 종료는 사용자 입력을 기다린다.

## 고정 예제

```text
R 입력             G 입력             B 입력
0 1 3 0 2          1 2 1 3 0          2 1 0 1 3
1 2 3 1 0          2 2 0 3 1          0 3 2 2 1
3 2 1 2 3          1 0 3 2 2          1 2 1 0 3
0 2 0 2 1          3 1 2 1 0          0 3 1 3 2
1 0 1 3 0          2 3 0 2 1          2 0 3 1 0

첫 R 곱            최종 출력
0 0 0              15 13 18
0 2 0              10 18 12
0 0 1              15 13 12
```

첫 RGB 식은 `R 3 + G 6 + B 6 = 15`, 다음 위치는 `R 6 + G 4 + B 3 = 13`이다. 출력값은 하드코딩하지 않고 고정 입력과 가중치로 계산한다.

## 중단·재시작과 확인 범위

씬 Manager는 먼저 소유 코루틴을 중단하고 체험 모듈의 Cancel을 호출한다. 모듈은 안내 음성을 정지한 뒤, 단계 Controller의 `Cancel`로 다음·재보기·배치·이동·퀴즈 입력 구독을 해제한다. 숫자 사본, RGB 합 사본, 잡기, 강조와 숨겨진 합계 글자를 정리한다. 직접 이동을 취소할 때 XR의 자유 위치 추적 설정을 복원한다. 다시 시작하면 모든 묶음을 숨기고 새 계산 객체, 빈 두 격자로 첫 배치 장면부터 시작한다. 내부 XR 리스너는 표시 생성부터 폐기까지 유지하고 폐기 시 해제한다.

2026-11-13 받침대 제거, 단계별 장면 전환, 자막·버튼 축소, 안내 음성, 출력값의 의미 마무리 장면 변경은 Unity 6000.3.24f1 배치 모드(Android 대상)의 임포트와 스크립트 컴파일만 확인했다. 컴파일 오류는 없고, 수정한 두 프리팹·씬과 음성 23개의 임포트에서 오류가 나오지 않았다. 프리팹과 씬은 에디터 없이 YAML을 직접 수정했다. Play·XR 조작·음성 청취·화면 배치 확인은 수행하지 않았으므로 슬롯 위치, 자막·버튼판 배치, 음성 속도와 연출 대기 시간은 실행 확인 전이다. 테스트 파일·플레이어 빌드는 생성하지 않았다.

책임 분리 리팩터링은 호출·이벤트 연결을 정적으로 검토했다. 이 변경에 대한 테스트·컴파일·빌드·Unity 실행은 수행하지 않았다. 기존 단계 순서와 음성 대기, 재보기 및 종료 버튼 동작을 유지했다.

## ROOM 1-1 행동 기반 RGB 관찰 (2026-11-13)

선택창과 RGB는 같은 48×27 PixelGridData를 사용한다. 돋보기를 잡아 이미지 위에서 같은 선택 칸에 1초 머무르면 RGB가 자동으로 펼쳐진다. 이미지 밖으로 나가거나 선택 칸이 바뀌면 머무르기 시간을 초기화한다. 손을 놓은 유효 선택도 유지된다. 원본 보드는 이동·축소하지 않으며 RGB 펼침 후에도 돋보기 입력을 유지한다.

PixelSelectionController는 이동 중 선택 칸이 바뀔 때 SelectionChanged를 알린다. CNNScreenLabManager가 해당 3×3을 읽어 PixelRevealStage.UpdatePatch에 전달한다. RGB 색과 숫자는 펼침을 반복하지 않고 갱신하며 변경된 숫자는 0.18초 동안 1.1배로 강조한다. 이미지 밖에서는 마지막 RGB 값을 유지한다. 설명 페이지는 제거하고 처음으로는 왼쪽, 관찰 마치기는 오른쪽에 둔다. 완료 후에도 관찰할 수 있다.

ScreenLabUIController는 연결된 AudioSource와 안내 클립 3개로 음성을 순서대로 재생한다. 첫 잡기, RGB 펼침, 펼침 이후 이동이 안내를 요청하며 같은 음성을 반복하거나 겹쳐 재생하지 않는다. 자동 사전 로드만으로는 음성이 시작되지 않는다. 리셋·비활성화·EndSession에서 음성을 중단한다. 화면에는 짧은 조작 문구만 표시한다.

2026-11-13 사용자 승인 후 Unity 6000.3.24f1 / D3D11에서 스크립트 컴파일과 CNNScreenLab Play 진입을 확인했다. 컴파일 오류와 확인 구간의 런타임 예외는 없었다. 기존 CS4014(ModelRealitySessionController)와 CS0414(PixelRevealStage._revealDuration) 경고는 남아 있다. Game View에서 XR 컨트롤러와 태블릿 렌더링을 확인했으며, 돋보기 1초 유지·RGB 갱신·음성의 실제 조작 검증은 수행하지 않았다. 플레이어 빌드와 테스트 파일은 생성하지 않았다.
