# 공장 공간과 체험 연결

[FactoryEnvironment.unity](../client/Assets/Scenes/FactoryEnvironment.unity)는 정문 앞마당, 튜토리얼실, 세 체험실, 연결 복도와 후문 하역 공간으로 구성한다. 중앙 복도를 공유하던 이전 구조를 순차적으로 통과하는 방 구조로 교체했다. 공장을 직접 실행하면 정문 앞에서 시작한다.

현재 구역에 따른 학습 단계와 태블릿 이동은 FactoryEnvironmentManager가 조율한다. 셔터 통행 조건은 FactoryShuttersManager가, 누적 학습 진행률·완료 기록과 태블릿 상태는 Core의 LearningSessionManager가 담당한다. FactorySceneLoadController는 FactoryAreaController의 AreaChanged만 구독해 이전·현재·다음 씬을 로드·언로드한다. 활성화 시 직접 처리나 자동 재시도는 하지 않는다. 로드된 체험은 하나의 목록으로 관리하며 결과를 로컬 C# 이벤트로 알린다. 세션은 로더에 로딩 명령을 보내지 않는다. 세 컴포넌트는 공장 씬과 함께 종료된다. 후문 구역 진입 시 CNNArchiveEnding을 Single로 로드하고, 일반 학습 콘텐츠는 Additive로 로드한다.

플레이어 입력 없이 배경 연출을 담당하는 `FactoryLightFaultController`, `FactoryFanController`, `LoungeClockController`는 `Scripts/FactoryEnvironment/Decorations/`에 둔다. 네임스페이스는 `FactoryEnvironment`이며 각 Controller가 담당 장식의 동작을 갱신한다.

## 공장 외형 보강

`FactoryEnvironment`에서 기존 공장 건축과 설비의 표시 메시, 재질, 조명을 보강했다. 콘크리트 벽은 거푸집 이음새와 타이홀, 실내 바닥은 약 1.8m 간격의 줄눈과 마모가 보인다. 기존 건축 메시 28개의 UV와 탄젠트를 재배치해 면 크기가 달라도 표면 결의 실제 크기가 일관된다. 실내 바닥 표시 9개는 `SealedConcreteFloor` 재질을 사용한다.

- 사물함·도장 장비에는 분체도장의 작은 찍힘, 철제 설비에는 연마 방향이 드러나는 금속, 연구 데스크와 상자·서류에는 각각 작업대 마감재와 종이 섬유를 적용했다. 연구용 배경 모니터에는 약한 자체 발광을 적용했다.
- 기존 직사각형 셔터 9개와 ROOM #1 아치 셔터의 표시 메시에 양면 압연 슬랫과 이음쇠를 만들었다. 가이드 레일과 상부 하우징에는 단차와 체결부를 넣었다. 이동 패널은 `GalvanizedShutter` 재질을 사용한다.
- ROOM #2의 컬럼형 관측 장비와 챔버형 분석 장비에는 라운드 외장, 가공 플랜지, 관측창 씰, 체결 볼트, 굴곡진 호스와 케이블을 기존 결합 메시에 적용했다.
- 정문 설비 마당의 가로 탱크 두 기는 통행로 쪽 단부를 접시형으로 다듬고 둘레에 육각 체결부를 배치했다. 원통의 몸체와 단부에 연마 결이 이어지도록 UV를 다시 배치했다.
- 기존 공간 채움용 점광원을 비활성화하고, 발광 등기구 표면에서 추출한 면광원과 실내 혼합 스폿 조명을 사용한다. 남쪽 연구실 책상 주변에는 기존 천장 등기구에 대응하는 면광원을 추가했다. 고정 표면에는 별도 라이트맵 UV를 만들고, 방별 반사 프로브와 이동 물체용 라이트 프로브를 배치한다. 조명 설정은 `Settings/FactoryLighting.asset`에 저장한다.

씬의 오브젝트 ID와 Transform, 충돌 영역, 셔터의 이동 방식과 체험 연결을 유지한다. 실내 등기구와 간접광을 다시 베이크해 라이트맵 2장과 방별 반사 프로브 5개를 생성했다. 데스크 주변과 튜토리얼 작업화·연구복은 데스크톱 Unity Play의 전후 화면에서 확인했다. Quest 기기 성능은 실측하지 않았다. 텍스처 출처는 [에셋 출처 및 저작권](ASSET_CREDITS.md)에 기록했다.

튜토리얼실과 ROOM #2에는 중앙 천장등 하나와 외곽 선형 등기구 네 개가 있다. 튜토리얼은 외곽등 세 개가 깨져 있으며 중앙등과 남은 외곽등의 세기를 낮췄다. ROOM #2는 대각선의 두 개가 깨져 있으며 중앙등과 외곽등 두 개로 바닥을 비춘다. ROOM #1-1은 검은 천장등 네 개를 사용한다. ROOM #1-2는 검은 두 줄 등기구 여섯 개를 사용한다. 서로 다른 행·열의 두 개는 형광관이 깨져 있으며 나머지 네 개는 각 형광관에 연결된 베이크 면광원을 사용한다. 깨진 등기구 일곱 개 아래에는 유리와 등기구 테두리 조각이 흩어져 있다. 휴게실에는 검은 천장등 두 개를 두고 스폿 조명의 세기와 범위를 낮췄다. ROOM #3은 바깥쪽의 검은 두 줄 등기구 네 개를 사용하며 각 형광관에 연결된 베이크 면광원을 사용한다. 책상 램프 일곱 개에는 소형 작업광을 연결한다. 현재 라이트맵과 반사 프로브는 이전 배치의 베이크 결과다.

정문 캐노피 아래 벽등 두 개의 점광원과 갓 밝기를 각각 절반으로 설정했다. [FactoryLightFaultController](../client/Assets/Scripts/FactoryEnvironment/Decorations/FactoryLightFaultController.cs)는 점광원과 확산판을 약 0.42초간 함께 깜빡이고 해당 위치에서 합선 효과음을 재생한다. 정문 벽등은 각각 5초 간격으로 2.5초 차이를 두고 깜빡이며 스파크 입자 40개와 20개를 연달아 방출한다. 연결 복도등의 주기는 7초다. ROOM #1에서 ROOM #2로 가는 복도와 ROOM #3에서 후문으로 가는 복도의 등기구는 줄 두 개로 천장에 연결한다. ROOM #1에서 ROOM #2로 가는 복도의 등기구에서 스파크가 두 번 튀며 인접 벽과 천장이 잠깐 밝아진다. 후문 복도는 꺾이기 전의 등기구 하나를 사용한다.

### 연구복과 가까이 보는 가구의 형태

튜토리얼 옷장의 연구복 세 벌은 열린 앞섶, 앞뒤 천 두께, 중력 방향으로 늘어진 소매와 열린 소맷단, 접힌 옷깃, 입체 주머니와 봉제선을 가진 곡면 메시다. 튜토리얼 바닥의 연구복에는 옷장에 걸린 베이지색 연구복과 같은 깃·앞섶·주머니·단추·소맷단과 재질을 사용한다. 몸판과 소매를 바닥에 맞게 펼쳐 접힘을 표현했다. 휴게실 바닥의 연구복에는 연속적인 굴곡을 적용했다. 청색 연구복 재질에는 기존 섬유 노멀 맵을 촘촘히 반복한다.

연구 데스크 의자 8개는 어깨 쪽으로 좁아지고 허리 쪽이 굽은 성형 등받이를 사용한다. 데스크·모니터 외장·수납함·상자 등의 각진 부품 271개에는 재질과 두께에 맞는 둥근 모서리를 적용했다. 기존 방별 결합 메시 안의 표시 형상을 수정했으며, 오브젝트 Transform과 Collider는 유지한다. 메시 인덱스·정점의 유한값·면과 노멀 방향을 정적으로 대조했다. 이 후속 수정의 Unity 렌더링과 Quest 성능은 확인 전이다.

### 근접 소품과 표시 내용

세 연구실 환풍기의 판형 날개는 반경에 따라 폭과 피치가 달라지는 곡면 날개로 수정했다. 휴게실의 매트리스·베개·접힌 침구와 옷걸이의 작업복에는 곡면, 부풀음과 접힌 깃을 적용했다. 튜토리얼 작업화 두 짝의 밑창은 발끝·아치·뒤꿈치 형태를 따르고, 중앙 홈과 분리된 트레드를 가진다. 갑피에는 패딩 칼라, 혀, 아일릿, 교차 끈과 매듭, 뒤꿈치 고리를 적용했다. 금속 보관함 39개는 기존 본체에 별도 손잡이, 잠금쇠와 체결부를 가진다. 기존 표시 오브젝트의 위치·종류와 충돌 영역을 유지한다.

문서 인쇄에는 `FactoryResearchPages` 재질과 아틀라스를 사용한다. 문서마다 별도 표본·문서 번호와 계산 내용을 배치하고, 실제 플레이 데이터와 혼동하지 않도록 설명용 계산 예시라고 적는다. 옷의 천 조각은 인쇄 서류에서 제외한다. 배경 계산 장비의 화면에는 `FactoryDiagnosticDisplays.png`의 계산 표본을 사용한다.

연구 데스크의 배경 모니터 16대에는 얇은 베젤, 후면 통풍구, 전원 표시등, 스탠드와 케이블을 적용했다. 12대는 진단 그래프·장비 기록·바탕화면·시계 등 9가지 정적 화면 구성을 사용하고 4대는 꺼진 패널을 사용한다. 키보드는 한영 각인과 숫자패드가 있는 104키 사무용 6대, 남색 포인트의 68키 컴팩트형 1대다. 마우스 7개는 곡면 외장, 분리된 클릭 버튼과 홈이 있는 휠을 사용한다. 유선 전화기 1개에는 받침과 수화기, 번호·기능 키, 코일선과 내선·회선 상태 화면을 적용했다. 데스크 아래 PC 본체 7대는 파노라마 유리형 2대, 전면 통풍형 3대, 알루미늄 프레임 유리형 2대로 나눠 배치하며 팬·그래픽카드·냉각 부품·포트를 모델링했다. 이 소품은 기존 데스크의 정적 표시 메시이며 해당 표면의 라이트맵 UV를 투영해 사용한다. 연구 데스크 모니터 16대와 휴게실 모니터 1대는 기존 화면 위에 서로 다른 충격점과 분기 패턴을 사용한다. 각 모니터 앞 상판에 얇은 유리 파편을 흩어 놓았다.

튜토리얼 동쪽 사물함 18개 문에는 눌러 성형한 면, 뒤로 들어간 통풍구, 곡선 손잡이, 경첩과 번호판을 적용했다. `TutorialLockerCoating` 아틀라스에는 문마다 다른 도장 마모와 찍힘을 배치한다. 선반 위 골판지 상자 35개는 접힌 덮개와 이음새, 눌린 모서리, 포장 테이프와 개별 재고 라벨을 사용한다. 나머지 케이스 38개에는 형태를 따라가는 보강 홈, 뚜껑 접합부와 손잡이를 적용하고, 청색 도장 금속·올리브색 도장 금속·성형 플라스틱에 다른 표면을 사용한다. 기존 배치와 충돌 영역을 사용하며, 교체한 표면은 기존 라이트맵 UV를 보존하거나 해당 표면의 UV를 투영해 사용한다.

휴게실 창과 배경 관측창의 `Factory/Thin Refractive Glass` 셰이더는 굴절률 1.5의 프레넬 반사와 얇은 유리의 화면 공간 굴절 근사를 사용한다. 카메라의 불투명 색상 버퍼를 읽으므로 화면 밖 물체와 다른 투명 물체의 정확한 굴절은 표현하지 않는다. 공장 카메라에서만 색상 텍스처를 요청하며, 반사 프로브에는 유리 레이어를 제외한다. 완전한 광선 추적이나 실측 광학 재현은 아니다.

### 연구실 벽 마감과 설비

튜토리얼·ROOM #1~#3·휴게실의 실내 벽에 회백색 패널을 적용했다. 벽 하단은 청회색 패널과 걸레받이 띠를 사용하며, 낮아진 ROOM #2의 기존 벽 하부 구조는 유지한다. `FactoryLabPanelCream`과 `FactoryLabPanelSlate`는 줄눈, 표면 결, 매끄러움이 다른 재질이다. 벽의 기존 위치와 충돌 영역을 사용한다.

ROOM #1~#3의 키 큰 사물함 9개는 기존 베이지색과 올리브색을 사용한다. 성형 문과 통풍구·손잡이·경첩·번호판, 선반과 행거가 있는 내부를 모델링했다. 문 두 개는 21°와 23° 열린 정적 표시이며, 문 자체의 얇은 충돌 영역을 추가했다. ROOM #1의 합성곱 관찰 콘솔은 아틀라스에서 계산 표본 한 장을 정방향으로 표시하고, 화면 위 안내 문구 오브젝트를 비활성화했다. 1-1과 1-2 사이 아치 위의 외장 덮개와 체결 장식은 제거했다.

환풍기 3대의 가드와 몸체는 고정되어 있다. `FactoryFanController`가 44초 주기마다 회전체를 두 번 가속하고, 회전 사이에는 약 18초 동안 멈춘다. 각 환풍기는 서로 다른 시점에 재시동하며, 해당 위치의 3D AudioSource에서 고음의 금속 마찰음을 재생한다.

ROOM 1-2 북서쪽 사물함 두 개에는 기존 베이지색을 살린 광택 도장과 금속 반사를 적용했다. 문 통풍구는 개구부를 가리던 루버 판을 제거해 내부 깊이가 보인다. 휴게실 북벽 사물함은 같은 청회색으로 통일하고 왼쪽에 두 개를 추가했다. 휴게 테이블과 의자 세 개, 동쪽 벽의 쿠션형 소파, 걸쇠에 외투를 걸 수 있는 스탠드를 새 표시 메시로 교체했다. 소파는 벽을 따라 0.43m 이동했고 북동쪽에 프린터 선반이 있는 데스크톱 책상을 배치했다. 흰색 조리 기기는 조작면이 방 중앙을 향하도록 90° 돌렸다. 바닥의 작업복 세 벌과 와인병·소주병 일곱 개는 새 형상을 사용한다. 휴게실 가구는 기존 라이트 프로브와 반사 프로브를 사용한다.

튜토리얼 옷장의 연구복 세 벌은 어깨가 옷걸이의 경사를 따라가도록 배치했고, 옷장 앞 바닥 연구복과 휴게실 외투에는 접힌 옷깃, 봉제선, 열린 소맷단과 주름을 추가했다. ROOM 1-2 칸막이 선반의 전면 보와 기둥 일부에는 녹 자국을 더했다. 관찰 콘솔의 앞면은 진단 화면을 표시하고 측면과 뒷면은 유광 검정으로 마감했다. ROOM 1의 현미경 네 대는 곡면 본체와 계단형 받침을 공유한다. 각 현미경의 기존 배치 방향에 맞춰 본체를 조정하고 접안부, 대물렌즈, 재물대를 연결했다.

휴게실 식탁에는 서로 다른 컵을 놓고 서류와 도시락통의 위치와 방향을 조정했다. 소파 쿠션과 침구는 가장자리를 둥글리고 천이 내려앉는 형태를 보강했다. 바닥 게임기 두 대에는 별도의 조작부와 화면을 배치했다. 조리 기기 받침장은 상판 및 주전자와 함께 90° 회전한다. 입구의 황흑 경고 테이프 뒤에는 기존 출입 차단 충돌체가 놓여 있다. `LoungeClockController`는 기기 현지 시각을 읽어 휴게실 벽시계의 시침·분침·초침을 표시한다.

## ROOM #1 내부 분리

ROOM #1은 X[-32,-12], Z[-14,6]의 20×20m 공간이다. 동쪽 입구 (-12,0,0)를 고정하고 이전 16×16m 외곽에서 서쪽 4m·남북 각각 2m를 확장했다. 체험 위치와 내부 문을 보존하기 위해 중앙 벽은 X=-20을 유지하고 양 끝만 새 외곽까지 연장한다. 동쪽의 체험 1-1(CNNScreenLab) 공간은 명목상 8×20m, 서쪽의 체험 1-2(CNNConvolutionLab) 공간은 12×20m다. 통로 중심은 (-20, 0, -8.8)이며 폭 3.2m·최고 높이 3.2m의 아치다. 벽은 천장까지 이어지고 아치형 금속 셔터가 통로를 닫는다. 같은 FactoryShutterController로 기존 문과 동일하게 1.6초 동안 3.3m 상하 이동한다. 벽·아치 상부와 셔터에 충돌 영역을 저장한다.

ScreenLab과 ConvolutionLab은 독립된 학습 단계다. 첫 공간은 픽셀 선택·RGB 전개 관찰, 두 번째 공간은 R/G 계산 학습·B 퀴즈를 담당한다. FactorySceneLoadController가 지역 진입 이벤트에 반응해 씬을 전환하고, FactoryShuttersManager가 퇴장 가능 상태와 양피지 수집 조건에 따라 문을 연다. Screen과 Convolution의 입장 문서는 모두 ID 0(01)이다. 내부 공유 문은 관찰 완료·문서 수집 후 열린다. 태블릿은 두 체험을 별도 항목으로 제공한다. 상세 책임과 수명은 [픽셀 관찰과 합성곱 체험](pixel-inspection.md)을 따른다.

ROOM #1 진입 경로는 오른쪽 체험으로 끝나고 다음 방 경로는 왼쪽에서 시작하며, 두 체험 사이에는 남쪽 아치를 지나는 별도 경로를 둔다. 외부 출구는 (-26,0,6)으로 옮기고 폭 3.2m를 유지한다. 복도2 세로 구간은 X[-27.8,-24.2], Z[6,10.2], 가로 구간은 X[-27.8,-12], Z[10.2,13.8]로 맞추어 기존 ROOM #2 입구 (-12,0,12)에 연결한다. 다음 방 안내선은 (-23,-1.5) → (-23,3) → (-26,3) → (-26,12)를 지나 고정 컨볼루션 표시를 우회하고 ROOM #2 서쪽 입구에서 끝난다.

## ROOM #2 높이와 ROOM #3 연결

특징 맵 체험은 서쪽부터 Y=0, -0.318, -0.636, -0.954, -1.272m의 발판을 지난다. ROOM #2의 공장 바닥은 가장 낮은 발판보다 5.8cm 아래인 Y=-1.33m에 두었다. 바닥의 줄눈은 `SealedConcreteFloor` 재질로 표현한다. 별도 검은 고무 격자 메시를 씬에서 제거했다. 공장 외곽의 연속 지면 메시에는 ROOM #2와 복도3의 범위에 맞춘 개구부를 두어 낮은 바닥과 계단이 보인다. 발판의 충돌 영역은 표시 메시의 옆면까지 이어진다. 가구·장비·소품과 해당 충돌 영역을 낮은 바닥에 맞췄고, 벽과 벽면 철제 기둥도 바닥까지 연장했다. 천장 하단은 Y=6.8m다. 서쪽 문 안의 Y=0 문턱은 기존 복도2 바닥을 체험의 첫 발판에 연결한다.

체험 발판은 ROOM #2 내부 X[-11.84, 11.793], Z[9.448, 14.552]에 있다. 폭은 5.104m다. 입력과 첫 Conv 사이의 계단을 서쪽으로 1.59m 옮겨 입력 발판을 줄이고 첫 Conv 발판을 늘렸다. 계단의 단 깊이와 높이는 유지했으며 발판 콜라이더, 테두리와 양쪽 난간의 단차를 새 경계에 맞췄다. 판정 통은 X≈10.705에 있어 동쪽 셔터에서 중심까지 약 1.3m다. 양옆 배경 소품은 X 방향으로 분산되어 있다. 라이트맵과 반사 프로브는 이전 배치에서 베이크한 데이터를 사용한다.

높이 약 65cm의 유리 난간이 발판 양쪽 가장자리를 따라 X=-11.84부터 X≈11.793까지 이어진다. 양끝의 중앙은 입구와 출구 통행을 위해 열려 있다. 두 난간은 같은 `Room02GlassRailing` 메시를 참조하며, 옆 통로에서도 XR 레이로 체험 패널을 조작할 수 있도록 표시용으로 배치했다.

동쪽 셔터는 낮은 바닥까지 닫힌다. 복도3은 X[12,15], Z[10.2,13.8]에서 8단을 올라 ROOM #3의 Y=0 바닥에 닿는다. 단 높이는 약 16.6cm이며 양쪽 셔터 앞에는 평평한 구간을 둔다. ROOM #3 안내선은 체험 발판과 복도 계단 높이를 따라간다.

## ROOM #3 높은 연구실 바닥

ROOM #3 단상·경사면·유리 난간을 중심 (23, 0, 12) 기준으로 80% 크기로 배치한다. 단상의 높이는 0.24m다. 서쪽 진입 경사면은 X[20.60,21.864], Z[11.456,16.04]에 걸쳐 있으며 기존 약 10.8° 경사를 유지한다. 북쪽 경사면은 Z[16.04,17.368]에서 출구 방향으로 내려가며, 경사면 끝에서 북쪽 셔터 앞까지 평평한 바닥이 이어진다. 두 경사면은 코너에서 연결된다. 단상과 경사면은 하나의 MeshCollider를 공유하고 퇴장 안내선은 축소된 경사면의 높이를 따라간다.

유리 난간은 Input 쪽 끝에서 공급 책상 뒤편을 지나 Output 쪽 꺾이는 가장자리까지 이어진다. ROOM #2의 유리·프레임 재질을 사용하고 단상에서 약 0.58m 높이로 배치한다. 사용자 쪽 긴 경사면과 북쪽 출입 구간은 열려 있다. 유리는 XR 레이와 이동을 막지 않는 표시용이다.

ROOM #3 서쪽 벽과 입구는 X=15에 둔다. 주변 가구·소품의 표시와 충돌체는 새 벽과 단상 사이에 재배치했다. 북쪽 연구 책상은 모니터·의자·책상 램프와 함께 반대편 남쪽 벽의 (X=17.3, Z=5.66)으로 옮겼다. 책상과 의자의 충돌체도 표시 메시를 따라 이동한다. 북쪽 벽 마감의 개구부는 X[20.4, 23.6], Z=19의 출구 셔터와 복도 중심 X=22에 맞췄다. 공급 책상은 조립 행 쪽으로 0.252m, 제어 패널은 0.084m 가까워졌다. 조립 슬롯 8개와 고정 Input·Output은 기존 간격을 사용한다.

태블릿의 모델 제작 도착점은 (22.42, 0.24, 12)이며 조립 행 앞을 향한다. 스틱 이동은 기존 XR CharacterController와 단상 Collider를 사용한다. 에디터 시뮬레이터의 WASD 이동은 Room #3의 단상과 경사면 높이에 맞춰 XR 리그의 기준 높이를 갱신한다.

`FactoryPlayerController`는 ROOM #2와 복도3에서 기존 XRBodyTransformer의 충돌 이동으로 리그를 아래로 이동시킨다. 이 구역에는 에디터 시뮬레이터의 WASD 이동 후 리그 높이를 보정하는 별도 컴포넌트가 없다. 태블릿의 특징 맵 도착점은 서쪽 진입 발판의 (-10.7, 0, 12)이며 동쪽을 향한다.

## 문과 안내선

튜토리얼실과 세 체험실에 각각 입구·출구 셔터가 있고, 후문 공간에는 입구 셔터가 있다. ROOM #1 내부 아치 셔터를 포함해 총 10개다. 셔터 패널은 Collider와 함께 1.6초 동안 위아래로 3.3m 이동한다. 모든 셔터는 닫힌 상태로 시작하며 별도의 초기 열림 설정은 두지 않는다. Awake에서 씬에 저장된 패널 위치를 닫힘 기준점으로 저장하고, Open·Close 요청에 따라 이동 애니메이션으로 개폐한다. AreaController가 카메라 위치로 접근을 판정하고, ShutterController는 전달받은 명령과 접근 상태로 패널을 움직인다. ShuttersManager가 접근 이벤트를 받아 통행 조건을 판단하고 해당 Controller를 제어한다. ShuttersManager는 공장 씬의 Factory Environment 오브젝트에 배치하며 실제 셔터 Controller 10개를 한 번씩 등록한다. 공유 셔터는 다음 체험실의 입구 조건에 따라 열리도록 처리한다.

FactoryLayoutData의 Inspector에서 _shutters 배열에 FactoryLayoutData.Shutter 10개를 등록한다. 각 항목은 셔터 ID(_id), 고정 문틀 Transform(_frame), 접근 거리(_approachDistance)를 저장한다. ShutterController에는 대응하는 ID와 패널 이동 설정을 두며 접근 거리는 중복 저장하지 않는다. 접근 기준점에는 움직이는 _panel이 아닌 고정 문틀 Transform을 연결한다. 모든 셔터의 접근 거리는 6m다. AreaController는 문틀과 카메라의 XZ 거리로 접근 여부를 계산하므로 문틀을 이동하면 판정 기준도 따라간다. 접근용 Collider나 별도 위치 좌표는 추가하지 않는다. 방의 기존 바닥 Collider와 우선 볼륨 참조는 유지한다.

AreaController는 Awake에서 같은 오브젝트의 FactoryLayoutData.Shutters를 직접 읽어 접근 판정 상태를 초기화한다. FactoryLayoutData.Shutter는 LayoutData 내부에 정의하고 직렬화하는 설정 객체이며 외부에는 읽기 전용 프로퍼티를 제공한다. AreaController는 ID별 접근 상태를 소유하고 상태 변경 시 ShutterProximityChanged(id, isNear)를 발행한다. ShuttersManager는 씬에 연결한 AreaController 참조를 사용해 자신의 OnEnable/OnDisable에서 ShutterProximityChanged를 직접 구독·해제한다. 일반 근접 개폐에서는 가까워지면 통행 조건을 확인해 열고, 멀어지면 닫는다. ShuttersManager는 재판정 시에도 AreaController.IsNearShutter를 직접 조회한다.

AreaController는 LateUpdate에서 셔터 상태를 먼저 계산하고 구역 변경과 셔터 이벤트를 알린다. 구역이 바뀌지 않아도 접근 판정은 계속한다. 닫힘 보류도 같은 IsNear를 사용한다. ShutterController는 실행 순서 100의 LateUpdate에서 이동하므로 같은 프레임에 갱신된 접근 상태로 닫힘을 보류한다. 문턱 위에 있지 않아도 접근 범위 안이면 닫히지 않으며, 범위를 벗어나면 대기 중인 닫힘을 이어간다. ShutterController에는 카메라 참조나 플레이어 위치 탐색이 없다.

1. FactoryRouteGuideController는 시작 시 튜토리얼 안내선을 켠다. LearningSessionManager의 StageAvailabilityChanged에서 퇴장이 가능하다는 알림을 받으면 LearningStageCatalog.Stages 순서에 따라 다음 체험의 안내선을 켠다. 마지막 체험 다음에는 후문을 안내한다. 목적지 씬이 로드되기 전에도 안내선을 표시한다.
2. FactoryRouteGuideController는 AreaChanged를 직접 구독해 도착 구역의 Stage가 표시 중인 목적지와 일치할 때 안내선을 끄고 목적지를 None으로 비운다. 방 진입 자체로 셔터를 닫는 명령은 보내지 않는다.
3. 셔터의 접근 범위를 벗어나면 닫고, 닫히는 중 다시 접근하면 닫힘을 보류한다. 개방 조건을 만족하면 다시 열린다. 정방향과 역방향 모두 동일한 셔터 ID·거리·개방 조건을 사용한다.
4. AreaChanged를 받은 로더가 _areaOrder의 바로 이전·현재·다음 Stage 씬을 준비한다. sceneLoaded에서 로더가 콘텐츠를 배치한 뒤 ContentLoaded(stage, scene)를 발행하여 세션이 Start 전에 초기 데이터와 이벤트 구독을 적용한다.
5. CanOpenShutter(id)는 현재 진행 방향 대신 StageSpace의 입출구 ID 관계로 해당 문에 연결된 체험을 확인한다. 개방 판단에는 로딩 중 여부나 씬 로드 여부를 사용하지 않는다. 최초 통행 허가는 출구라면 해당 체험의 퇴장 가능 상태, 입구라면 LearningStageCatalog.Stages의 이전 체험 퇴장 가능 상태와 해당 입장 양피지를 확인한다. 튜토리얼 입구는 접근하면 열리고, 후문은 마지막 체험의 퇴장 가능 상태를 확인한다. 공유 아치 문은 Screen 출구와 Convolution 입구 조건을 함께 확인한다.
6. ShuttersManager는 LearningSessionManager의 StageAvailabilityChanged와 ParchmentManager의 Collected를 직접 구독해 개방 조건을 재판정한다. ShuttersManager가 현재 접근 상태를 조회해 가까운 문을 재판정하므로 문 앞에서 기다리다가 조건이 충족되어도 열린다. 조건 변경은 자동 개방을 대기 중인 출구도 재판정한다. 로더는 기존처럼 AreaChanged로 필요한 씬을 준비하고 유지 범위 밖 씬을 정리한다.
7. 플레이어가 접근 범위 안에 있고 닫힌 셔터를 열 수 없으면 `FactoryShuttersManager`는 해당 `FactoryShutterController`에 안내 표시를 요청한다. 양면 World Space 안내판 `Prefabs/FactoryEnvironment/ShutterUnavailableSign.prefab`은 ROOM #1-1에서 ROOM #1-2로 가는 아치 문과 ROOM #1-2·#2·#3 출구에만 배치한다. 문구는 “체험을 완료해야 문을 열 수 있습니다”다. 문이 열리거나 접근 범위를 벗어나면 안내판을 숨긴다. ROOM #2 출구의 안내판은 특징 맵 체험이 판정 단계에 처음 도달하면 숨긴다. 문 개방 조건은 체험 완료로 유지한다.
8. FactoryShuttersManager는 LearningSessionManager의 StageAvailabilityChanged를 직접 구독한다. 체험에서 퇴장이 가능해지면 FactoryLayoutData.GetStageSpace(stage).ExitShutter로 출구를 조회하고 셔터당 한 번 자동 개방을 요청한다. 기존 개방 조건이 충족되면 접근 범위 밖에서도 출구를 열고 안내판을 숨긴다. 플레이어가 6m 안에 들어온 뒤 다시 밖으로 나가면 문을 닫고 일반 근접 개폐로 돌아간다. 개방 시 이미 6m 안에 있으면 접근한 것으로 처리한다. ShuttersManager는 출구마다 자동 개방 대기와 접근 여부를 관리한다.

ROOM #1과 ROOM #2 입구의 바닥 투사 안내는 `ShutterFloorHologram.prefab`의 바닥 높이와 패널 기울기를 공통으로 사용한다. 각 `FactoryShutterController`가 해당 인스턴스의 투사 표시, 패널과 스캔 라인을 참조하고 펼침·접힘을 갱신한다. ROOM #2 입구에서는 `FactoryShuttersManager`가 직전 체험의 완료 여부와 입장용 양피지 수집 여부를 확인해 남은 조건을 전달한다. 표시 문구는 입구의 바닥 홀로그램에서 갱신된다.
9. 후문 구역에 들어가면 FactoryRouteGuideController가 목적지 도착으로 안내선을 끈다. FactoryPlayerController가 AreaChanged를 직접 받아 로드된 체험의 잡은 물체를 해제한다. 로더는 구역 이벤트 전달이 끝난 다음 프레임에 OpeningEnding의 CinematicTransitionController로 CNNArchiveEnding 전환을 요청한다. 1초 게이트 진입 연출로 가린 후 Single로 활성화하고, 0.6초 도착 연출이 끝나면 엔딩 본편이 시작된다. 실패하면 LoadFailed로 알리고 중단한다. 자동 재시도하지 않으며 다음 AreaChanged 때 다시 처리한다.

스틱 이동은 공용 리그의 기존 CharacterController와 벽·셔터 Collider를 사용한다. 에디터 FPS의 WASD는 시뮬레이터의 몸 추적 위치를 직접 바꾸므로 스틱 이동의 충돌 확인을 대신하지 않는다.

통행을 처음 허용한 셔터 ID는 ShuttersManager의 _permittedShutters에 현재 공장 세션 동안 보관한다. 실제 문은 이탈 시 닫히지만 통행 허가는 체험 초기화·씬 언로드 후에도 유지되므로 재접근과 역방향에서도 다시 열 수 있다. 공장 씬을 새로 시작하면 통행 허가는 초기화된다. 태블릿 이동 시에는 별도의 CloseAll을 호출하지 않고 이동 후 AreaController의 거리 판정으로 이전 문을 닫고 새 문을 처리한다.

바닥선은 폭 0.12m·두께 0.012m이며, 중심은 해당 발판이나 바닥보다 0.025m 위에 있다. 화살촉은 직전 크기의 0.75배로 줄여 날개 폭 0.0675m, 뒤쪽 길이 0.75m·좌우 폭 0.375m(각 날개 약 0.839m)다. 각 구간 시작에서 1.6m 뒤에 첫 화살표를 두고, 직전 간격 5.5m의 1.5배인 8.25m 간격으로 배치했다. 현재 목적지 경로 5개의 화살촉은 19개이고 ROOM #1 내부 경로에 4개가 더 있다. FactoryRoute.mat의 청록색 (0.08, 1, 0.8)과 그림자·프로브 설정은 유지한다.

튜토리얼을 포함한 다섯 체험 모두 ILearningExperience를 구현한다. Progress·ProgressChanged와 EndSession은 Core 세션이 기록·종료 처리에 사용하고, CanExit·ExitAvailabilityChanged는 세션이 구독해 공장에 전달하며 문 개방 판단에 사용한다. LearningProgress는 체험별 최대 도달 진행률을 보관하며 1에 도달하면 완료를 기록한다. LearningProgressSnapshot은 LearningStageCatalog.Stages 전체의 동일 비중 평균을 계산하며 재방문·초기화로 감소하지 않는다. 튜토리얼은 최종 미션 확인 후 입력을 복원하고 ProgressChanged(1), ExitAvailabilityChanged(true)를 순서대로 알린다. 튜토리얼만 완료하면 전체 진행률은 20%, 다섯 체험을 모두 완료하면 100%다.

누적 완료는 공장 씬 수명의 LearningSessionManager가 소유한 LearningProgress에만 저장한다. 태블릿은 읽기 전용 LearningProgressSnapshot을 표시한다. 공장 세션 안의 재방문·체험 초기화·태블릿 비활성화는 기록을 지우지 않으며, 공장 씬이 종료되면 세션과 학습 기록을 폐기한다. 재진입은 새 세션이다. 기존 공용 양피지의 수집 기록 수명은 별개다.

로더와 공장·세션·플레이어는 OnEnable/OnDisable에서 로컬 C# 이벤트를 연결·해제한다. 로더는 공장과 태블릿의 동작 메서드를 호출하지 않으며, 외부에서 호출하는 Load·Unload·Prepare 진입점도 제공하지 않는다. 공장과 세션은 로더의 결과 이벤트와 읽기 전용 IsBusy·IsLoaded 조회를 사용한다. 체험 내부 모듈의 연결과 구체적인 동작은 각 체험 Manager가 담당한다. 파일 경로와 기존 스크립트 meta GUID는 유지한다.

구역 데이터 클래스는 FactoryLayoutData.Area 하나다. Id, 연결된 Stage, 우선 볼륨 Collider, 바닥 Collider 목록을 읽기 전용 프로퍼티로 제공한다. FactoryLayoutData._areas에 모든 구역과 None을 씬 데이터로 저장한다. Stage는 직렬화할 때 LearningStageId.None으로 체험이 없는 구역을 표시하고, 공개 Stage 프로퍼티는 이 값을 null로 반환한다. 기존 구역 판정 순서와 Collider 참조를 유지한 채 AreaController에서 LayoutData로 이전했다. None은 볼륨과 바닥이 없는 항목이다.

FactoryLayoutData는 Areas와 GetArea(id)로 같은 Area 객체를 제공한다. _areaOrder는 진행 순서의 구역 ID만 저장하며 별도 Area 객체를 만들지 않는다. TryGetAdjacentAreas(area, out previous, out next)는 진행 순서에 포함된 구역이면 true와 바로 이전·다음 Area 객체를 반환한다. 양 끝의 인접 구역은 null이며 진행 순서 밖의 구역이면 false를 반환한다.

FactoryAreaController에는 별도의 Area 클래스나 직렬화된 구역 목록이 없다. Awake에서 같은 오브젝트의 LayoutData와 None 구역을 확보하고, LateUpdate에서 LayoutData.Areas를 사용해 위치를 판정한다. ContainsVolume·ContainsFloor·Contains 비교 함수는 모두 AreaController에 있다. CurrentArea는 판정된 Area 객체이고 AreaChanged도 같은 객체를 전달한다. Manager와 로더는 전달된 Stage와 LayoutData의 인접 구역 조회를 사용하며 순서 배열이나 인덱스에 직접 접근하지 않는다. PlayerController는 area.Stage가 Exit이면 로드된 체험의 잡은 물체를 해제한다.

FactoryLayoutData는 체험별 입출구 셔터 ID·경로·콘텐츠 기준점을 StageSpace로 묶어 StageSpaces와 GetStageSpace(stage)로 제공한다. LayoutData는 내부 Shutter 클래스로 셔터 데이터 형식을 직접 정의하고 _shutters에 보관하며 Shutters로 제공한다. FactoryShutterId도 FactoryAreaId와 같이 FactoryLayoutData.cs에서 정의한다. 외부 셔터 데이터 형식이나 셔터 동작 컴포넌트에 의존하지 않는다. ShutterController 참조는 ShuttersManager의 배열에만 연결한다. Screen 출구와 Convolution 입구는 동일한 ScreenToConvolution ID를 사용하며, 후문 구역의 출구 ID는 None이다. ShuttersManager는 실제 Controller 배열을 사용하므로 공유 문을 중복 등록하지 않고 존재하지 않는 후문 출구도 참조하지 않는다. ROOM #1에서 두 체험 구역 볼륨 밖의 공용 바닥은 InspectionRoom이다. Screen 볼륨은 중심 X=-16, 폭 5.6m로 Convolution 볼륨과 겹치지 않는다. LearningStageCatalog는 체험 목록·씬 이름·양피지 조건을 제공한다.

## 구역 이름과 공간 범위

구역 식별 enum FactoryAreaId는 FactoryLayoutData.cs 파일의 FactoryEnvironment namespace에 클래스와 나란히 정의한다. Area.Id와 LayoutData의 순서·구역 조회가 이 타입을 사용한다. CurrentArea와 AreaChanged는 FactoryLayoutData.Area 객체를 사용한다. 통로의 Area ID와 씬 오브젝트 이름은 연결된 두 공간의 이름을 사용한다. 숫자로만 구분하던 통로 이름을 FrontCourtToTutorialRoom, TutorialRoomToInspectionRoom, InspectionRoomToFeatureMapRoom, FeatureMapRoomToModelDesignRoom, ModelDesignRoomToRearCourt로 변경했다. ID의 직렬화 숫자는 유지한다. 외부의 서쪽·동쪽 바닥은 Outside(ID 8) 한 항목의 두 floorVolumes로 묶고, FrontCourt와 RearCourt는 별도 Area로 유지한다.

공간 범위는 FactoryLayoutData._areas에 연결된 Collider 참조와 FactoryEnvironment 씬의 Transform·BoxCollider 값으로 저장한다. 위치 포함 여부 계산은 FactoryAreaController가 담당한다. 아래는 월드 좌표이며 단위는 m다. 바닥 판정은 X·Z만 검사하고 우선 볼륨은 높이도 검사한다. ROOM #2 우선 볼륨의 하단은 바닥 Y=-1.33m다.

## 로딩 수명

FactoryAreaController는 Start에서 공용 XROrigin의 카메라 Transform을 직접 확보한다. 각 FactoryShutterController는 닫힌 상태로 시작하며 Awake에서 패널의 닫힘 기준점을 저장한다. FactoryPlayerController는 Start에서 플레이어를 정문에 배치한다. 첫 LateUpdate에서 배치된 위치로 구역과 셔터 접근을 판정한다. 이후에도 LateUpdate에서 위치를 판정한다. 로더가 받는 프로젝트 이벤트는 AreaChanged 하나다. 튜토리얼 씬은 구역 진입으로 준비되며 튜토리얼 입구 셔터는 접근하면 열린다.

진행 순서에 등록되지 않은 구역은 기존 씬을 유지한다. 등록된 구역의 Stage가 null이면 해당 항목의 씬만 생략하고 바로 이전·다음 항목의 Stage는 처리한다. 빈 Stage를 넘어 더 먼 항목을 탐색하지 않는다. 처리 중 새 체험 구역 이벤트가 오면 진행 중인 비동기 작업을 마친 뒤 최신 구역을 처리한다. 정상 처리 후에는 이전·현재·다음 체험만 남긴다. 로더는 LayoutData에서 조회한 이전·다음 Area와 전달된 현재 Area의 Stage로 required 목록을 만든다. None은 생략하고 이미 로드된 씬은 재사용하며 누락된 씬을 순서대로 로드한다. 필요한 씬 준비가 끝난 뒤 목록에 포함되지 않는 씬을 정리한다. UpdateScenes는 한 번의 목록 갱신만 수행한다. 처리 중 새 AreaChanged가 오면 최신 위치와 대기 플래그를 저장하며, 진행 중인 로드·해제가 끝나면 남은 이전 요청 작업을 생략한다. 대기 이벤트가 있는 경우에만 다음 UpdateScenes를 시작하고, 없으면 IsBusy를 해제하고 끝낸다. while 반복이나 자동 재시도는 없다.

로더는 Stage와 Unity Scene을 저장한다. sceneLoaded에서 ILearningExperience가 있는 콘텐츠 루트를 찾고 다른 루트를 비활성화한 뒤 ContentAnchor의 위치·회전·배율을 적용한다. 콘텐츠 조명을 비활성화하고 Rigidbody 위치·회전을 동기화한 뒤 ContentLoaded(stage, scene)를 발행한다. 세션은 이 알림에서 ILearningExperience를 찾아 초기 데이터·진행률 구독을 연결한다. 이 작업은 Start 전에 끝난다. 로딩 처리가 끝나면 StateChanged로 IsBusy 변경을 알린다. FactoryEnvironmentManager는 AreaChanged를 직접 구독해 현재 단계를 갱신한다. 체험 초기화로 진행 불가가 되어도 유지 범위 안 씬은 해제하지 않는다.

Screen 구역 진입 시 로더가 Convolution을 미리 로드한다. 각 체험은 Start에서 자체 초기화하고 내부 사용자 입력에 따라 진행하며, 공장의 구역 진입·이탈 상태를 전달받지 않는다. 세션은 구체 체험 Manager를 참조하지 않고 ILearningExperience로 상태 구독·진행 기록·종료 요청만 처리한다. 두 씬 사이에 픽셀 데이터를 전달하지 않으며, Convolution은 항상 자체 고정 5×5 RGB 예제를 사용한다. Screen의 선택 변경이나 재시작은 Convolution의 입력·진행 상태를 초기화하지 않는다. 기존 문 개방 조건과 학습 순서는 유지한다.

ContentUnloading은 모든 구독자의 정리 코루틴을 기다린다. 세션은 구독 해제와 EndSession을 담당하고, FactoryPlayerController는 ContentUnloading을 직접 구독해 해당 씬의 잡은 물체를 해제한다. 두 구독자의 정리가 끝나면 로더가 씬을 언로드한다. FactoryPlayerController의 로더·구역 Controller 참조는 공장 씬에 연결한다. 후문 진입 시에는 FactoryPlayerController가 AreaChanged에서 Stage가 Exit인 Area를 받아 로드된 체험의 잡은 물체를 직접 해제한다. CurrentStage·StageChanged는 공장이 소유한다. 로더에는 StageEntryStarted·NextSceneReady·현재 단계 상태가 없다. 실패 시 LoadFailed를 발행하고 처리를 끝낸다. 실패 후 타이머나 재시도 코루틴은 없으며 새 AreaChanged만 다음 처리를 시작한다.

앞마당–튜토리얼 통로에서 튜토리얼을 준비하고, 튜토리얼–ROOM 1 통로에서 픽셀 관찰 씬을 준비한다. 튜토리얼 완료는 다음 문을 여는 조건이며 로딩 시작 조건이 아니다. 앞마당에서는 튜토리얼을 시작하지 않는다. 입력 초기화와 종료는 공통 콘텐츠 수명 절차로 처리한다.

태블릿 StageMoveRequested는 공장과 세션이 구독한다. FactoryEnvironmentManager는 Awake에서 TabletManager를 한 번 찾아 보관하고 OnEnable에서 기존 HandleStageMoveRequested를 연결하며 OnDisable에서 해제한다. 종료 시 태블릿이 먼저 파괴된 경우에는 해당 구독 해제를 생략한다. 공장은 이동 가능 여부를 확인하고 플레이어를 목적지로 옮긴다. FactoryAreaController가 LateUpdate에서 위치를 판정해 발생시킨 AreaChanged가 도보 진입과 동일한 로딩 경로를 사용한다. 공장의 TravelStarted·TravelFinished를 받아 세션이 태블릿 안내를 갱신한다. 같은 구역을 다시 선택하면 도착점으로 이동하며 체험을 재시작하지 않는다. 로드되지 않은 체험으로 이동하면 위치 이동 뒤 콘텐츠 로딩이 진행된다. 세션은 요청 기준으로 문서를 지급하며 로딩을 지시하지 않는다.

로더는 공장 종료 시 로드된 체험 목록을 정리하고 로딩 중 종료되면 완료 콜백으로 뒤늦게 로드된 씬을 정리한다. 후문 전환은 영속 XR 리그의 OpeningEnding CinematicTransitionController가 실행한다. 로더는 전환 요청 전에 Single 전환 상태를 표시해 Unity의 씬 정리와 중복 언로드하지 않으며, 실패하면 이 상태를 해제하고 기존 LoadFailed를 알린다. Additive 학습 씬 로딩·배치는 기존 로더가 담당한다.

## 지도·양피지

미니맵 형상은 TabletMiniMapController가 Start에서 최초 생성하고 TabletManager.SetMapData에 직접 전달한다. 재활성화 시에는 OnEnable에서 기존 지도 데이터가 있으면 다시 생성해 전달하고, OnDisable에서는 자신이 전달한 데이터를 ClearMapData로 해제한다. 이름이 structural slab으로 끝나는 바닥 Collider와 concrete를 포함하는 벽 Collider의 XZ 영역, 실제 Pickup 위치를 읽는다. 지도 컴포넌트는 공장 진행과 독립적으로 동작하며 FactoryEnvironmentManager와 LearningSessionManager는 지도 연결에 관여하지 않는다. 셔터 상태를 동적으로 지도에 그리는 기능은 없다.

## 씬·에셋 관리

## 공장 오클루전 컬링

FactoryEnvironment의 고정 배경에 Unity 내장 베이크 오클루전 컬링을 적용한다. 기존 XRPlayerRig 카메라의 Occlusion Culling 활성 설정을 사용하며, 씬은 `Assets/Settings/FactoryOcclusionCullingData.asset`을 참조한다. 기존 GI·배칭·반사 프로브 Static 플래그는 유지하고, 고정 MeshRenderer 413개에 Occludee Static을 추가했다. 그중 불투명한 콘크리트 벽·바닥·구조물 37개는 Occluder Static도 사용한다. 이는 비활성 배치를 포함한 설정 수이며 실제 프레임의 렌더러 수가 아니다.

움직이는 셔터 패널, 환풍기 회전체, 시계 바늘과 양피지 Pickup 하위는 정적 베이크 대상에서 제외한다. 100m를 넘는 bounds를 가진 외곽 배경과 달도 정적 베이크에서 제외하며 기존 Dynamic Occlusion 설정을 유지한다. 큰 결합 메시를 분할하지 않았으므로 일부가 보이는 결합 메시 전체가 컬링에서 살아남을 수 있다.

셔터 10개의 고정 Controller 오브젝트에 OcclusionPortal을 배치하고 `_occlusionPortal`로 연결한다. Portal의 중심과 크기는 닫힌 패널 Collider를 문틀 로컬 좌표로 변환한 값이다. 일반 셔터는 3.2×3.2×0.22m이며 낮은 ROOM 2 출구는 3.2×4.53×0.22m다. `FactoryShutterController.Open()`은 움직임 전에 Portal을 열고, `Close()` 및 `LateUpdate()`는 패널이 완전히 닫힌 `_amount == 0`에서만 Portal을 닫는다. 닫힘 보류와 이동 도중 재개방 동안 Portal은 열린 상태를 유지한다. 충돌·학습 진행·씬 로딩은 기존 소유자가 처리한다.

Factory Environment 루트의 OcclusionArea는 로컬 중심 (0, 2, 8), 크기 (80, 10, 90)의 View Volume이다. 베이크 값은 Smallest Occluder 5m, Smallest Hole 0.25m, Backface Threshold 100이다. 공장만 열어 베이크하며, 로드 후 재배치하는 Additive 체험 씬을 고정 배경 데이터에 포함하지 않는다. 체험 씬의 활성 전환 및 동적 오브젝트 컬링 결과는 실행 확인 전이다.

## 태블릿 자유 이동

LearningSessionManager는 태블릿의 StageMoveRequested(LearningStageId)를 받아 선택한 단계까지의 ParchmentIds 문서를 카탈로그 순서대로 지급한다. FactoryEnvironmentManager는 같은 이벤트로 플레이어를 이동시킨다. 로더는 FactoryAreaController의 LateUpdate 판정 결과인 AreaChanged만 받는다. 지급은 이동 요청 기준이며 이동 거절·실패·이전 단계 복귀에도 회수하지 않는다. 문서 지급은 체험 완료를 뜻하지 않는다.

태블릿 카드의 순서·요청 ID는 LearningStageCatalog.ProgressStages의 기존 네 항목에 연결하고 고정 제목 Text는 기존 프리팹을 유지한다. ProgressStages 이름은 기존 태블릿 코드와의 호환을 위해 남기며 전체 진행률 계산에는 사용하지 않는다. 전체 진행률·완료 개수·총 개수는 튜토리얼을 포함한 Stages의 다섯 항목으로 계산한다. CountsForProgress 같은 제외 플래그는 없다. 누적 완료와 진행률 계산은 Core가 맡고 TabletLearningController는 LearningProgressSnapshot과 이동 안내를 표시한다. 세션 연결 해제 시 빈 스냅샷을 전달한다. 공장 씬 재진입 때 학습 기록은 새로 시작하며 기존 ParchmentManager의 수집 기록 수명은 별도로 유지한다.
