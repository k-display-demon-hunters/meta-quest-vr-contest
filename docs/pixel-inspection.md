# 픽셀 관찰과 합성곱 체험

## 씬과 진행

두 체험은 Core/Learning의 동등한 학습 단계다. 진행 순서는 Tutorial → ScreenLab → ConvolutionLab → FeatureMap → ModelDesign이다. LearningSessionManager가 단계·양피지 조건·이벤트 연결을 조율하고 FactorySceneLoadController가 준비·배치·활성화·언로드한다.

CNNScreenLab은 이미지·돋보기 선택, 선택한 3×3 픽셀의 RGB 전개와 원래 0~255 값 관찰까지 담당한다. 픽셀 설명과 RGB 세 페이지를 확인한 뒤 관찰 마치기를 누르면 완료한다. 이동 대기 중에는 관찰 결과를 유지하며 처음으로를 누르면 현재 체험의 완료 상태를 초기화한다. 세션의 누적 최대 진행 기록은 유지한다.

CNNConvolutionLab은 스크린 없는 입체 RGB 계산 체험이다. 연습용 0~3 값 소개 → 별도의 0/1 가중치 등장 → R 계산 안내 → G 계산 안내 → B 퀴즈 → 결과 확인을 한 공간에서 진행한다. 각 채널의 가중치는 대각선 세 칸이 1이고 나머지가 0이다. B 퀴즈는 화면의 숫자 키패드로 값을 입력하고 답 확인 버튼으로 제출하며 오답은 수정 후 재시도한다. 자동 배치는 물리 조작만 보조한다.

## 데이터와 책임

Screen의 PixelImageFactory가 기존 OpeningBroadcast.png를 128×72 축소·5×5 블러·32×18 샘플링한다. 선택 시 PixelPatchData에 Color32 9개를 복사한다. 관찰 표시는 원래 값을 사용한다. 세션은 다음 Convolution을 준비할 때 Screen 진입점의 SelectedPatch를 읽어 Convolution 진입점의 SetInput에 전달한다. 전체 이미지·좌표·Transform·계산 객체는 전달하지 않는다.

직접 Convolution으로 이동하거나 단독 실행하면 코드에 명시된 기본 9픽셀 예제로 시작하며 UI에 기본 예제임을 표시한다. 순차 진행은 직전 Screen의 선택값을 사용한다. ConvolutionCalculation이 성분별 RoundToInt(value × 3 / 255)로 int[3,9]를 만든다. 관찰 원본은 변경하지 않는다.

## 공간과 에셋

Screen과 Convolution의 입장 문서는 모두 ID 0(표시 번호 01)이다. 내부 셔터는 Screen 출구와 Convolution 입구가 공유한다. 관찰 완료·다음 씬 준비·문서 수집을 모두 충족하면 열리고 두 번째 영역 진입 시 닫힌다. 다음 씬 준비만으로 공유 셔터를 열지 않는다. 준비 이후 Screen을 초기화하면 세션이 다음 씬을 취소하고 입구·안내선을 닫는다.

공장의 기존 공간·문·경로·콘텐츠 기준점을 일반 목적지 데이터로 연결한다. Convolution 기준점의 배율은 2이며 기존 콘텐츠 표시 크기를 유지한다. 태블릿은 픽셀 관찰·합성곱·특징 맵·모델 제작 네 체험을 제공한다. 전체 진행은 네 체험의 평균이며 Convolution은 R/G/B 완료에 따라 1/3씩 진행한다.

Screen의 로드 기준 위치에서 첫 픽셀 선택 화면은 화면 왼쪽으로 0.15m, RGB 전개 화면부터 관찰 종료 안내까지는 화면 오른쪽으로 0.5m 이동한다. PixelBoardController가 씬에 연결된 전체 콘텐츠 루트에 각 오프셋을 절대 적용하므로 이미지·돋보기·RGB·설명·버튼이 함께 이동하고, 반복 전환·초기화로 이동량이 누적되지 않는다. 기존 MoveAside 축소 이동은 유지하며 처음으로를 누르면 첫 화면 위치로 복원한다. 공장의 Y 회전 -90°에서 화면 오른쪽은 월드 +Z이며, 루트 위치는 첫 화면 (-17.6,0,-2.60), RGB 화면 (-17.6,0,-1.95)다.

Prefabs/CNNScreenLab의 FilterDisplay·ImagePixelGrid·RgbPixelStack은 관찰 전용이다. Prefabs/CNNConvolutionLab/PixelCalculationUI.prefab은 계산 전용이다. 기존 .meta와 GUID를 보존해 이동했으며 두 씬 사이에 계산 UI 인스턴스를 공유하지 않는다. 원본 이미지는 Textures/CNNScreenLab/OpeningBroadcast.png, 관찰용 재질은 Materials/CNNScreenLab에 둔다. 파일 내용·GUID와 기존 폰트 라이선스 고지를 유지한다.

ScreenLabBuilder와 ScreenLabVisualsBuilder는 관찰 표시만 연결하고 ConvolutionLabBuilder는 학습 모듈·전용 계산 프리팹을 연결한다. 저장된 씬에 같은 참조를 반영했다.

## 합성곱 계산 작업대

`Prefabs/CNNConvolutionLab/ConvolutionWorkbench.prefab`은 RgbVolumeController와 고정 작업대(상판·지지대·거치대·명판), 입력·필터 대기·필터 정렬·곱 결과·합계·이동 계산식의 기준 Transform을 보관한다. CNNConvolutionLab 씬과 ConvolutionLabBuilder가 같은 프리팹을 연결한다. 작업대의 로컬 배율 1.5와 위치 (0,0,-0.55)는 프리팹에 저장하며 안내 UI와 평행하게 배치한다. 고정 작업대는 R 층을 꺼내는 단계부터 G/B 전환 중에도 계속 표시하고 도입 및 최종 요약에서는 숨긴다. 지지대 길이와 발 높이는 공장의 바닥 Y=0에 맞춘다. 공장 콘텐츠 기준점·배율·동선은 유지한다.

입력 타일은 어두운 몸체·RGB 데이터 면·중성색 숫자 면으로 나뉜다. 가중치는 얇은 금속 프레임과 홈이 있는 손잡이를 가지며, 활성 필터 손잡이에도 잡기 Collider가 연결된다. 결과판은 테두리와 뒷판을 갖고 미계산 칸은 점으로 표시한다. 합계는 별도의 테두리 표시부에 나타난다. 고정 작업대의 세 재질은 `Materials/CNNConvolutionLab/`에 있다. 타일·필터·숫자와 기존 연산 표시는 GeometryBuilder가 실행 중 생성한다. 일반 타일의 발광은 제거하고 배치 안내에만 약한 발광을 사용한다.

RgbVolumeController가 프리팹 기준점을 내부 계산·표시에 연결한다. KernelInteractionController는 전달받은 대기·정렬 기준점으로 필터를 복귀·배치하고, CalculationAnimationController는 계산식 기준점을 사용한다. 이동 숫자와 연결선은 각 숫자 표시의 실제 위치에서 출발한다. 씬 Manager나 다른 모듈에는 내부 기준점을 공개하지 않는다.

PixelCalculationUI는 상단 제목·행동 안내, 입력 아래의 마지막 계산식, 하단 계산 메모·피드백·고정 다음 버튼으로 배치한다. R/G 안내 계산은 현재 줄의 최대 세 계산식만 메모에 남기고 다음 줄에서 비운다. 누적 합은 별도 표시하며 계산 규칙·줄 단위 진행은 유지하고 B 답변은 고정 숫자 키패드를 사용한다. R 계산을 기준으로 만든 외형과 배치는 같은 표시 구현을 사용하는 G/B에도 적용된다. 최종 결과는 중앙의 1200×850 요약 패널에서 채널별 합 → 편향을 포함한 계산식 → 출력값 설명 순서로 표시한다. 이때 작업대는 숨기고 학습 마치기 버튼을 패널 안에 둔다.

### 필터 배치 피드백

KernelInteractionController가 필터의 대기·호버·이동·배치 가능·복귀·정렬·완료 상태를 관리한다. RgbVolumeController의 WaitForKernel이 배치 대기 중에만 UpdatePlacement를 호출한다. 상태가 바뀔 때 목표 형태·손잡이 홈의 색과 발광·안내 문구를 갱신한다. 상단 배치 안내 Text는 ConvolutionWorkbench의 Equation anchor 아래에 저장하고 `_placementHint`로 연결한다. 계산이 시작되면 배치 안내를 숨겨 이동 계산식과 겹치지 않게 한다.

| 상태 | 표시와 동작 |
| --- | --- |
| 대기·호버 | 고정 크기 점선 목표, 손잡이 강조와 Grip 안내. 호버 시 손잡이 발광을 높임 |
| 잡고 이동 | 화살표와 필터 제목을 숨기고 점선 목표로 이동하도록 안내 |
| 배치 가능 | 목표를 따뜻한 색의 실선으로 전환하고 놓기 안내. 입력 채널의 초록색과 완료 상태를 혼동하지 않도록 녹색에 의존하지 않음 |
| 범위 밖에서 놓기 | 0.30초 동안 원래 거치대로 복귀한 후 다시 잡기 가능 |
| 정렬 | 0.18초 동안 목표 위치·회전으로 이동. 이동 중 다시 잡기는 비활성화 |
| 완료 | 목표 옆 체크와 완료 안내를 0.45초 표시한 후 계산 진행 |

배치 가능 표시와 놓기 판정은 동일한 월드 거리 0.3m 이하 조건을 사용한다. 기존 회전 추적 비활성 설정을 유지한다. 자동 배치는 잡은 필터의 선택을 해제하고 같은 정렬·완료 경로를 사용하며, 정렬 중 반복 요청으로 이동 시간을 다시 시작하지 않는다. 부모로 돌아올 때 월드 크기를 보존한다. 채널 전환·종료 시 이동과 안내를 취소하고 배치 상태를 초기화한다. 이 피드백은 R/G 안내와 B 퀴즈의 공통 필터 배치에 적용된다.

### 한 칸의 곱셈과 누적 합

R/G 안내 계산은 현재 한 칸의 입력·가중치에만 얇은 테두리를 표시한다. 원본 숫자는 제자리에 유지하고 사본만 이동한다. CalculationAnimationController는 같은 모듈의 RgbVolumeController와 LessonUIController를 사용해 입체 표시와 안내판의 계산식·누적 합 갱신 시점을 맞춘다. RedCalculationController는 채널·칸 순서, 줄별 기록과 다음 버튼 대기를 담당한다. 계산값은 기존 ConvolutionCalculation을 그대로 사용한다.

1. 대응하는 입력·가중치를 0.25초 강조한다.
2. 숫자 사본을 0.45초 동안 계산식 위치로 옮긴다.
3. 전체 곱셈식을 0.70초 표시한 뒤 결과 숫자만 0.40초 동안 결과 칸으로 옮긴다.
4. 결과 숫자와 작은 체크를 기록하고 0.22초 유지한다. 미계산 칸은 흐린 점이며, 계산 결과가 0인 칸은 숫자 0과 체크를 남긴다.
5. 기록된 숫자를 유지하면서 `+ 값` 사본을 0.35초 동안 합계 표시부로 옮긴다.
6. `이전 합 + 값 = 새 합`을 0.65초 보여주고 채널 합 표시로 돌아간다. 0도 같은 경로로 처리하며 합이 유지된다는 안내를 표시한다.

연결선은 각 단계의 두 위치만 연결한다. 곱셈식 전체를 결과 칸이나 합계 칸으로 이동하지 않는다. 결과·합계 이동은 작은 곡선과 SmoothStep을 사용하며, 현재 행·열과 9칸 중 진행 위치를 안내판에 표시한다. 다음 줄 시작 시 이전 줄의 메모를 비운다. 다음 채널 Focus에서 결과 숫자·체크를 초기화하며, 단계 종료·비활성화 시 이동 사본·강조 테두리·연결선은 함께 숨긴다. B 퀴즈의 정답 공개도 같은 결과 기록 표시를 사용하지만 안내 계산을 자동 실행하지 않는다.

### 채널 진행 표시와 전환

PixelCalculationUI의 상단 안내판에 R·G·B 카드 세 개를 저장하고 LessonUIController의 Text·Image 배열로 연결한다. 안내판은 1400×300이며 아래 경계를 유지한 채 카드·제목·설명 영역을 분리한다. 설명 높이는 130으로 Noto Sans CJK KR 34 크기의 두 줄을 수용하고, 본문은 보통 굵기로 표시한다. 작은 RGB 색 띠는 채널을 구분하며, 진행 상태는 색에만 의존하지 않고 `대기`, `진행 중`, `완료 · 합 n` 문구로 표시한다. 완료한 채널은 따뜻한 색으로 표시하고 다음 채널에서도 합을 유지한다. 합이 0인 경우에도 완료로 표시한다.

RedCalculationController가 각 채널을 시작할 때 BeginChannel을 호출하고 9칸 계산·합 확인을 마치면 CompleteChannel에 누적 합을 전달한다. ConvolutionQuizController는 B 입력 준비부터 진행 중으로 표시하며 정답을 제출한 경우에만 합과 완료 상태를 공개한다. 오답은 B를 진행 중으로 유지한다. B 준비 시 이전 G 계산식·누적 합·피드백은 비워 두고 완료한 R/G 합은 카드에서 확인한다. LessonUIController는 전달받은 완료 합을 표시용으로만 보관하며 학습 순서나 정답을 판정하지 않는다. BeginCalculation에서 세 카드의 기록을 함께 초기화한다.

RgbLayerInteractionController는 각 채널을 꺼내기 전에 입력 층과 대기 가중치를 0.55초 동안 SmoothStep으로 준비 위치에 배치한다. 현재 보이는 층은 현재 위치에서 이동하고 숨겨진 층은 작업대 근처에서 나타나므로 숨겨 둔 먼 위치를 가로질러 오지 않는다. 이동 중에는 잡기·호버 연결선·자동 배치를 활성화하지 않는다. 이동이 끝나면 해당 채널의 층만 잡을 수 있고 기존 자동 배치도 다시 제공한다. Focus 이후에는 해당 채널만 계산 공간에 표시한다. 필터는 현재 보이는 해당 채널의 대기 가중치 위치에서 거치대로 이동한다. 처음 가중치가 나타날 때는 목표보다 0.16m 위에서 크기 0.85→1로 이동해 안내판을 가로지르지 않는다. 층 상호작용 종료 시 호버로 확대했던 숫자도 원래 크기로 복원한다. 층 꺼내기 안내는 상단 패널에서만 표시한다.

### B 퀴즈 숫자 키패드

PixelCalculationUI의 고정 키패드는 계산판 아래의 (0,-420)에 1400×440 크기로 표시한다. 키는 `1 2 3 / 4 5 6 / 7 8 9 / × 0 ←` 순서이며 140×72 크기, 가로 20·세로 10 간격이다. 가운데 숫자 키 위에는 어두운 입력값 표시부, 왼쪽에는 계산·삭제 안내, 오른쪽에는 입력·오답 피드백과 370×88 답 확인 버튼을 둔다. 얇은 구분선은 입력을 가로채지 않는다. 삭제 키는 갈색, 답 확인은 금색과 어두운 글자로 구분한다. 공장 배치에서 패널 하단은 Y=0.34m, 제출 버튼 하단은 Y=0.424m여서 바닥에 묻히지 않는다. 기존 XR UI 레이와 마우스 클릭을 사용하며 물리 키보드 입력은 추가하지 않았다.

LessonUIController는 최대 두 자리의 숫자 입력을 보관하고, ×는 전체 삭제, ←는 마지막 자리 삭제를 수행한다. 앞의 0에 숫자를 입력하면 해당 숫자로 교체한다. 빈 입력은 `답: —`로 표시하고 제출을 비활성화하며, 입력한 0은 유효하게 제출할 수 있다. 패널을 열고 닫거나 학습을 다시 시작할 때 입력을 초기화한다. 현재 계산의 정답 범위는 0~9지만 두 자리 오답도 입력·수정할 수 있다.

답 확인 시 정수 값으로 AnswerRequested 이벤트를 보내고 ConvolutionLessonManager가 ConvolutionQuizController.SubmitAnswer로 전달한다. 정오답은 기존 ConvolutionCalculation의 B 합과 비교한다. 오답은 입력값과 키패드를 유지하고 수정 안내를 표시한다. 정답은 즉시 키패드를 닫고 B 완료 카드·합계·계산 결과를 공개한다. 퀴즈 중에는 기존 계산 메모·계산식·합계 표시를 숨기고 정답 후 다시 표시한다.

기존 세 개의 객관식 버튼, 무작위 보기 생성, 입체 숫자 답 블록 생성 및 AnswerInteractionController와 해당 .meta를 제거했다. 입력 층 꺼내기·필터 배치와 그 자동 배치는 유지한다.

### 안내와 도착 방향

계산 메모는 현재 줄의 세 식만 유지하고, 줄 계산이 끝나면 상단에서 다음 줄 또는 합 확인을 안내한다. 물리 조작 대기 중에는 계산 메모 오른쪽에 입력 자동 배치 또는 필터 자동 배치를 표시한다. 요청은 현재 대기 중인 조작에만 적용한다. Exercise에서 계산 메모 배경을 먼저 그린 뒤 누적 합과 자동 배치 버튼을 그려 배경에 가리지 않게 한다. 태블릿 합성곱 도착점은 (-21.5,0,-3.4), Y 회전 -90°로 안내판 정면을 바라본다. 걸어서 입장할 때의 이동·방향은 바꾸지 않는다.

필터 프레임은 0.72×0.68 크기로 입력 숫자 바깥에 놓이며 숫자를 가로지르던 내부 세로 막대는 두지 않는다. 손잡이·잡기 영역·점선 배치 목표도 이 크기에 맞춘다. 대기 가중치는 각 숫자 뒤의 0.17×0.15 타일과 전체 뒷판을 어둡게 표시해 뒤쪽 층의 숫자가 틈으로 비치지 않게 한다. 실제로 입력 위에 겹치는 이동 필터에는 뒷판을 두지 않는다. 옆면 숫자는 두께가 있는 입력·결과 블록에만 표시하며 얇은 가중치 타일에는 만들지 않는다.

## 확인 범위

2026-11-04 Unity 6000.3.24f1의 FactoryEnvironment Play에서 기본 예제로 다음 항목을 확인했다.

- 입력·필터 자동 배치, R/G의 행별 계산과 채널 전환, R 합 5·G 합 6.
- B 키패드의 빈 답 제출 차단, 오답 0 제출과 입력 유지, 앞자리 0 교체, 두 자리 제한, 한 자리 삭제·전체 삭제, 정답 7 제출과 9칸 결과 공개.
- R 5·G 6·B 7과 최종 `5 + 6 + 7 + 0 = 18`, 편향 설명, 학습 마치기 이후 화면 종료.
- 두 줄 안내·키패드 피드백·결과 요약의 가독성과 바닥 가림 해소.

전체 흐름 확인 중 계산 메모의 그리기 순서를 바로잡았다. 이후 저장된 프리팹을 새로 불러와 Play를 재실행하고 자동 배치 버튼·누적 합 표시와 R 첫 줄 계산을 다시 확인했다. 필터 외곽·숫자 옆면을 수정한 뒤 입력 9개가 가려지지 않는 것을 확인했으며, 마지막 대기 가중치 뒷판 추가 후에는 별도 재실행으로 뒤쪽 숫자의 비침이 사라진 것을 확인했다. 최종 코드의 Unity 에디터 컴파일은 통과했고, 해당 실행 로그에서 컴파일 오류·런타임 예외는 발견하지 못했다. 기존 PixelRevealStage._revealDuration 미사용 필드 경고(CS0414)는 남아 있다.

에디터 검증에서는 태블릿 이동에 Play 한정 GraphicRaycaster와 버튼 Raycast Target을 임시 적용했다. 종료 버튼에 마우스와 시뮬레이터 XR 레이가 동시에 놓이면 마우스 입력이 반응하지 않는 경우가 있어 해당 XR Ray Interactor를 Play에서만 끄고 종료를 확인했다. 이 임시 설정은 저장하지 않았다. Quest 빌드·실기기 Grip 조작·시야·성능과 자동 테스트는 확인하지 않았다.

관찰 UI는 ScreenLabUIController, 관찰 씬 생성 메뉴는 ScreenLabBuilder가 담당한다. 과거 필터 패널·네온 노드·전용 XR 프리팹과 그 미사용 재질·메시·셰이더, 과거 시안 이미지는 참조 확인 후 삭제했다.
