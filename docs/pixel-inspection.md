# 픽셀 관찰과 ROOM 1-2 체험

## 진행과 완료 경계

Core/Learning의 단계는 `Tutorial → ScreenLab → ConvolutionLab → FeatureMap → ModelDesign`이다. ROOM 1-2의 `CNNConvolutionLab`에서는 1-1에서 본 그림에 필터 하나를 올려 한 자리의 출력값을 계산하고, 필터로 그림을 훑어 특징 맵 한 장을 채운다. 결과를 확인한 뒤 ROOM 2의 `CNNFeatureMapLab`으로 이어진다.

필터 배치 20%, 첫 출력값 45%, 특징 맵 완성 90%로 진행률을 갱신한다. 이어서 합성곱과 특징 맵을 짧게 정리하고 **체험 마치기**를 안내한다. 버튼을 누르면 `CNNConvolutionLabManager`가 `Progress=1`과 `CanExit=true`를 알린다. 누적 진행률은 `LearningProgress`가 체험별 최댓값으로 기록한다.

## 독립적인 관찰과 합성곱 입력

`CNNScreenLab`은 숫자 2 색점판에서 선택한 3×3 RGB 0~255 관찰을 담당한다. 첫 화면에는 원본 텍스처를 표시한다. `PixelImageFactory`는 같은 원본을 128×72로 축소하고 5×5 블러를 적용한 뒤 32×18로 샘플링해 픽셀 관찰에 사용한다. `PixelImageData.CapturePatch`가 만든 `PixelPatchData`는 관찰 내부에서만 사용하며 `Scripts/CNNScreenLab/PixelPatchData.cs`에 둔다. 외부로 선택 데이터를 공개하거나 전달하지 않는다.

`CNNConvolutionLab`은 1-1과 같은 색점판 원본 텍스처를 직접 참조하고, `Scripts/CNNConvolutionLab/Picture/PictureSampler.cs`가 1-1과 같은 순서로 32×18 픽셀 배열을 만든다. 순차 입장, 태블릿 직접 이동, 단독 실행 모두 같은 그림을 사용한다. 1-1의 선택 여부나 완료 상태로 입력을 바꾸지 않고, 1-1의 데이터나 코드를 전달받지 않는다. 계산 결과는 이 배열과 필터로 매번 계산한다.

`FactorySceneLoadController`는 인접 씬을 미리 로드한다. ScreenLab과 ConvolutionLab은 로드 후 각자의 `Start`에서 자체 초기화하며, 공장의 현재 구역이나 실제 입장 여부를 전달받지 않는다. ConvolutionLab은 입력 그림을 준비하고 필터 배치 입력을 기다린다. 공장 내 로드와 단독 실행은 같은 시작 경로를 사용한다. 로드된 상태에서는 구역 이동만으로 체험을 중단하거나 초기화하지 않는다.

`LearningSessionManager`는 구체 체험 Manager를 참조하지 않고 `ILearningExperience`로 단계·진행률·출구 허용 상태를 조회하고 변경 이벤트를 구독한다. 언로드 전에는 같은 인터페이스의 `EndSession`으로 정리를 요청한다. 공장 셔터의 개방 조건은 [Factory Environment](factory-environment.md)의 셔터 동작을 따른다.

두 체험의 UI 버튼은 공용 `XRPlayerRig`에 구성한 EventSystem·XRUIInputModule을 사용한다. `ScreenLabUIController`와 `CNNConvolutionLabManager`는 입력 환경을 생성하거나 해제하지 않으며, 버튼의 기존 On Click 연결로 각 체험의 요청을 처리한다. 체험 종료·언로드 시 공용 입력 환경은 유지된다. ScreenLab 단독 실행은 씬에 배치된 공용 리그를 사용하고, 자체 리그가 없는 ConvolutionLab의 XR 조작은 공장에 로드된 공용 리그를 사용한다.

## ROOM #1-1 픽셀 큐브 미리보기

`Floating image board/Low resolution image`의 `PixelGridData`는 색점판 원본을 칸별 면적 평균으로 48×27 RGB 배열에 저장한다. `GetColor(x, y)`와 `TryWorldToGrid`는 왼쪽 아래 칸을 (0, 0)으로 사용한다. 원본 텍스처의 Read/Write가 필요하다.

같은 오브젝트의 `PixelShatter`는 단위 Cube 메시와 `PixelGridCubes` 재질을 사용한다. 기본 상태는 숨김이다. Inspector 컴포넌트 메뉴의 `ShowGrid`와 `HideGrid`로 전환한다. 표시 중에만 원본 렌더러를 가리고, 숨길 때 기존 상태로 복구한다. 큐브는 최대 250개씩 인스턴싱해 그린다. Play 중에는 돋보기의 기존 `SelectionChanged`가 처음으로 유효한 3×3 선택을 알릴 때 0.3초 이미지 페이드와 1초 큐브 전개를 시작한다. 기존 선택 중심을 48×27 좌표로 변환해 해당 3×3을 강조한다. RGB 확대도 같은 중심의 9개 색을 `PixelGridData.GetColor()`로 읽어 채널 표시와 숫자판에 전달한다. 실시간 갱신 경로에서는 RGB 값을 Console에 출력하지 않는다. 다시 놓으면 강조 위치만 갱신한다. 같은 위치에서 1초 관찰한 뒤 RGB 펼침이 시작되면 큐브 연출을 중단하고 원본 이미지를 복구한다. ‘처음으로’도 연출을 중단하고 원본 렌더러 상태를 복구한다.

## ROOM #1-1 돋보기 전시대

`CNNScreenLab` 씬의 `CNN Screen Lab/MagnifierPedestal` Transform이 전시대 위치를 정한다. 받침대 윗면은 지름 0.56m, 바닥 기준 높이 1.0m에 있고 `MagnifierDock`은 윗면에서 0.175m 위에 있다. 시작하거나 선택을 초기화하면 돋보기는 이 기준점으로 돌아온다. 전시대에는 충돌 영역을 두지 않으며 기존 파란 바닥 표시는 비활성 상태로 보존한다.

전시대 위 돋보기의 `MagnifierIdleFloat`는 초당 30° 회전하고 0.5Hz로 ±3cm 움직인다. 기존 `XRGrabInteractable.selectEntered`에서 멈추고 ‘처음으로’의 `ScreenLabUIController.ResetRequested`에서 다시 시작한다. 잡힌 상태의 리셋 요청은 기존 동작과 같이 무시한다.

돋보기에는 짙은 금속 테두리와 반투명 렌즈가 있다. 같은 잡기 이벤트에서 `MagnifierPickupFX`가 렌즈 가장자리의 하늘색 띠를 먼저 반짝인다. 0.14초 뒤에 빛기둥이 0.4초에 걸쳐 꺼지기 시작하고, 전시대 링은 기존 밝기의 22%로 낮아진다. 돋보기 위치에서 최대 0.5초 동안 하늘색 파티클을 표시한다. Inspector의 `pickupClip`에 클립을 연결하면 공간 효과음을 재생한다. ‘처음으로’는 조명을 복구하고 다음 첫 잡기 연출을 준비한다.

## 공중 합성곱 구성

받침대 없이 입력 그림·수식 판·특징 맵을 공중에 띄우고, 단계마다 필요한 묶음만 보여 준다. 공장 콘텐츠 기준점은 `(-28.55, -0.3, -2.0)`, Y 회전은 -90°, 콘텐츠 배율은 1.2, 내부 Workbench 배율은 1.15다. 표시판과 자막·버튼판을 함께 담는 씬의 `Floating pixel values`는 배율 1.25, 높이 1.98이며, 전체 표시 크기는 이 배율 하나로 조절한다. 표시판 뒤에 별도 배경은 두지 않는다.

입력 그림, 수식 판, 특징 맵, 필터 명판은 `ConvolutionWorkbench.prefab`에 월드 공간 UI로 저장한다. 수식 판의 프레임 높이는 공장 씬 기준 약 1.80m이며, 제목과 합은 판 중심에서 위아래로 약 0.73m에 놓인다. Scene 뷰와 Prefab Mode에서 입력 원본과 빈 특징 맵을 볼 수 있다. 수식 판을 편집할 때는 `Output group`을 끄고 `Formula group`을 켠다. 위치는 각 그룹의 Transform에서 조정한다.

| 단계 (`FocusLayout`) | 보이는 묶음 |
| --- | --- |
| `Picture` | 왼쪽의 입력 그림과 배치용 필터 |
| `PictureAndFormula` | 왼쪽의 입력 그림과 필터, 오른쪽의 수식 판 |
| `PictureAndMap` | 왼쪽의 입력 그림과 필터, 오른쪽의 특징 맵 |

입력 그림은 같은 위치를 유지한다. `FocusLayoutController`는 오른쪽의 수식 판과 특징 맵의 표시 여부만 바꾼다. 플레이가 시작되면 입력 그림을 샘플링한 텍스처로 갱신하고, 특징 맵에는 계산한 값을 기록한다. 움직이는 필터와 수식 숫자 연출은 런타임에 생성한다. 필터의 첫 목표(`KernelTarget anchor`)는 계산한 첫 위치의 그림 칸 위에 놓인다.

| 공간 요소 | 현재 표시 |
| --- | --- |
| 입력 그림 | ROOM 1-1의 숫자 2 색점판을 32×18 픽셀 격자로 표시한다. 한 칸은 Workbench 로컬 0.05이며 그림은 1.6×0.9다. 숫자는 표시하지 않는다. |
| 필터 | 손잡이 하나와 연결된 RGB 세 프레임. 그림의 3×3칸(0.15)을 정확히 덮도록 축소한다. 앞의 빨강 층에만 분류 학습에서 얻은 칸별 가중치 아홉 개를 소수 둘째 자리까지 표시하고, 초록·파랑 층은 프레임만 둔다. 세 프레임은 하나의 잡기 대상으로 함께 움직인다. 시작 위치는 그림 오른쪽 앞이며 제목은 `필터 · 빨강 층`이다. |
| 수식 | 3×3으로 놓이는 아홉 개의 `값 × 가중치` 항과 그 합(소수 첫째 자리). 항은 필터의 해당 칸 위에 나타나 수식 판의 자리로 이동한다. 음수 가중치는 `17 × (-0.51)`처럼 괄호로 묶어 표시한다. 수식 판에는 행과 열 사이에 연한 회색 구분선을 두고, `빨강 층 · 겹친 아홉 칸` 제목과 초록·파랑 층의 가중치가 0이라는 안내를 표시한다. |
| 특징 맵 | 30×16칸. 값이 없는 칸은 회청색, 값이 기록된 칸은 `출력값÷255` 밝기의 회색이다. 필터의 현재 위치에 해당하는 칸에 테두리를 두고 아래에 `이 자리의 출력값`을 표시한다. |
| 자막 | 초점 아래의 자막 막대 한 줄에 현재 단계의 짧은 안내를 표시한다. 자세한 설명은 안내 음성이 담당한다. |
| 조작 | 오른쪽 버튼판에 주 동작·일시정지·처음으로 버튼만 배치한다. |

배치 단계의 손잡이 안내는 필터 근처에 표시한다. `PixelCalculationUI.prefab`에 자막 막대와 버튼판의 배치가 저장되어 있다. 버튼은 공용 `WorldUIButton`의 중첩 인스턴스다.

오른쪽의 주 동작 위치에 필터 자동 배치, 자동으로 훑기, 체험 마치기를 단계에 따라 표시한다. 현재 사용할 수 있는 주 동작 버튼의 금색 테두리는 밝아졌다 어두워진다. 일시정지 중에는 체험 재개 버튼을 강조한다. 일시정지는 연출 시간·안내 음성·필터 입력·자동 채우기를 멈춘다. 처음으로는 현재 코루틴과 입력, 음성을 정리하고 첫 배치로 돌아간다.

자막·안내·음성 문구는 모두 ‘~입니다’ 어체를 쓴다.

## 안내 음성

`LessonNarrationController`가 단계별 음성을 한 번에 한 줄씩 재생한다. 음성 파일은 `client/Assets/Audio/CNNConvolutionLab/ConvolutionNarration_<Cue>.wav`이며, 씬의 `Lesson narration` 오브젝트가 `NarrationCue` 순서로 참조한다. 새 음성을 요청하면 재생 중인 음성은 멈춘다.

AudioSource는 초점 중앙에 둔 3D 음원이며 6m까지 원래 크기, 14m에서 들리지 않도록 선형으로 줄어든다. 씬은 입장 전에 미리 로드되므로, 청자(`Camera.main`)가 9m 밖에 있을 때 요청된 음성은 보류했다가 범위 안으로 들어오면 재생한다. 카메라가 없는 단독 실행에서는 바로 재생한다.

수식과 출력 기록처럼 설명이 필요한 연출은 해당 음성이 끝날 때까지 다음 연출을 기다린다. 필터 배치를 기다리는 음성은 진행을 막지 않는다. 훑기 단계는 안내 음성이 끝나기 전에는 자동 채우기로 넘어가지 않는다(버튼을 누른 경우 제외). 음성은 `LessonPlayback`의 배속을 따르지 않는다. 출력값은 실행 중에 계산하므로 음성은 숫자를 읽지 않는다.

## 계산 규칙

입력은 32×18×3(RGB 0~255), 필터는 3×3×3, stride 1, 패딩 없음, 편향 0이며 활성화 함수는 쓰지 않는다. 빨강 층의 가중치는 숫자 정답으로 학습한 R-only CNN의 첫 Conv 채널 7(0부터 센 번호)에서 가져온 실제 float32이고 초록·파랑 층은 모두 `0`이다. 대략 `[0.128475, 0.555714, -0.165759; 0.620212, 0.274826, -0.777433; 0.205255, -0.356444, -0.506978]`이며 정확한 값은 `PictureConvolution.RedWeights`에 있다. 양수·음수가 함께 있어 출력은 가중 평균이 아니며 0~255 범위에 제한되지 않는다. 필터 왼쪽 위 `(row,column)`은 특징 맵의 같은 좌표에 대응하고, 특징 맵은 30×16(480칸)이다.

기존 컬러 MNIST 1·2·3의 실제 RGB를 16×16으로 줄이고 R만 사용해 숫자 분류를 학습했다. 검증 이미지의 위치별 반응 변화가 가장 큰 첫 층 채널을 선택했으며, 사람이 설계한 목표 필터·마스크 회귀·학습 후 계수 보정·양자화는 사용하지 않았다. 가중치 라벨·수식 항은 같은 원본 배열을 소수 둘째 자리까지 반올림해서 표시하고 합산은 원본 float32로 한다. 기존 밝기 표시 `value/255`는 유지되어 음수는 검게, 255 초과는 흰색으로 포화된다. 출력 숫자에는 원래 부호 있는 합이 남는다. 재현 코드·모델·검증 결과는 [가중치 제작 기록](../mnist-color-data/learned-filters/README.md)에 있다. R-only·편향 0·활성화 없음과 안내 단계는 유지한다.

`PictureSampler`는 1-1의 `PixelImageFactory`와 같은 순서(128×72 축소 → 5×5 블러 → 32×18 샘플링)로 원본 텍스처를 읽어, 1-1에서 본 것과 같은 픽셀 그림을 만든다. `PictureConvolution`이 이 픽셀 배열로 칸 값과 출력값을 계산한다. 출력값은 저장하지 않고 필요할 때 계산한다. 첫 배치 위치는 `StrongestWindow()`가 고른 출력값이 가장 큰 자리다.

## 진행 순서

전달 목표는 합성곱 연산의 과정·원리와 출력값이 어떻게 쓰이는지다. 숫자 계산은 한 자리에서만 보여 주고, 필터 하나가 그림에서 특징을 뽑아 특징 맵 한 장을 만드는 과정을 그림으로 보여 준다. 괄호 안은 그 단계의 장면이다.

1. **필터 올리기 (`Picture`):** 입력 그림과 오른쪽 앞의 필터를 표시한다. 반투명 필터 미리보기와 점선 목표를 따라 Grip으로 필터를 놓는다. 그림 면에서 본 목표와의 거리가 로컬 0.15(약 0.259m) 안이면 정렬하고, 밖이면 시작 위치로 돌아간다. 깊이 방향 거리는 보지 않는다. `필터 자동 배치`도 제공한다. 배치가 끝나면 진행률 20%다.
2. **곱하고 더하기 (`PictureAndFormula` → `PictureAndMap`):** 필터가 덮은 빨강 층 아홉 칸에서 `값×해당 칸의 가중치` 항이 하나씩 필터 칸 위에 나타나 수식 판으로 이동한다. 처음 두 항은 천천히, 나머지는 빠르게 놓인다. 아홉 항이 모이면 합을 표시한다. 이어서 항과 수식 판이 사라지고 같은 자리에 특징 맵이 나타나며, 공중에 남은 합이 특징 맵의 같은 자리 칸으로 들어가 그 칸이 밝기로 표시된다. 진행률 45%다.
3. **훑어서 채우기 (`PictureAndMap`):** 필터를 잡고 그림 위를 움직이면 필터가 칸 단위로 붙어 이동하고, 지나간 자리마다 특징 맵의 같은 칸이 채워진다. 손이 빠르게 지나가 건너뛴 칸도 경로를 따라 채운다. 필터는 그림 밖으로 나가지 않는다. 60칸을 채우고 안내 음성이 끝나거나 `자동으로 훑기`를 누르면, 남은 칸을 왼쪽 위부터 행 순서로 자동으로 채운다(초당 약 120칸). 잡은 상태에서 일시정지하면 잡기를 해제한다. 진행률 90%다.
4. **출력 설명 (`PictureAndMap`):** 입력 그림과 완성된 특징 맵을 나란히 둔다. 합성곱과 특징 맵을 정리한 다음 `체험 마치기` 버튼을 안내한다. 셋째 자막과 함께 버튼을 표시하며, 눌러야 100% 및 출구 허용 상태가 된다.

`LessonPlayback`의 공통 배속은 1.5배다. 장면 전환은 사라지는 구간 약 0.27초, 나타나는 구간 약 0.23초다. 배치, 훑기와 종료는 사용자 입력을 기다린다. 필터를 배치하면 완료 자막을 표시하고 수식 단계로 넘어간다. 안내 음성은 모두 합쳐 약 67초다.

PixelSelectionController는 이동 중 선택 칸이 바뀔 때 SelectionChanged를 알린다. CNNScreenLabManager가 해당 3×3을 읽어 PixelRevealStage.UpdatePatch에 전달한다. RGB 색과 숫자는 펼침을 반복하지 않고 갱신하며 변경된 숫자는 0.18초 동안 1.1배로 강조한다. 이미지 밖에서는 마지막 RGB 값을 유지한다. 설명 페이지는 제거하고 처음으로는 왼쪽, 관찰 마치기는 오른쪽에 둔다. 완료 후에도 관찰할 수 있다.
