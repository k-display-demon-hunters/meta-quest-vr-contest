# 픽셀 관찰과 ROOM 1-2 체험

## 진행과 완료 경계

Core/Learning의 단계는 `Tutorial → ScreenLab → ConvolutionLab → FeatureMap → ModelDesign`이다. ROOM 1-2의 `CNNConvolutionLab`에서는 5×5 RGB 입력에 필터를 배치하고 아홉 출력 위치를 계산한다. 결과를 확인한 뒤 ROOM 2의 `CNNFeatureMapLab`으로 이어진다.

출력값을 기록할 때마다 진행률을 갱신하며 아홉 칸을 모두 기록하면 95%에 도달한다. **결과 확인**을 누르면 3×3 결과와 첫 위치의 RGB 합산식을 표시한다. **체험 마치기**를 누르면 `CNNConvolutionLabManager`가 `Progress=1`과 `CanExit=true`를 알린다. 누적 진행률은 `LearningProgress`가 체험별 최댓값으로 기록한다.

## 독립적인 관찰과 합성곱 입력

`CNNScreenLab`은 숫자 2 색점판에서 선택한 3×3 RGB 0~255 관찰을 담당한다. 첫 화면에는 원본 텍스처를 표시한다. `PixelImageFactory`는 같은 원본을 128×72로 축소하고 5×5 블러를 적용한 뒤 32×18로 샘플링해 픽셀 관찰에 사용한다. `PixelImageData.CapturePatch`가 만든 `PixelPatchData`는 관찰 내부에서만 사용하며 `Scripts/CNNScreenLab/PixelPatchData.cs`에 둔다. 외부로 선택 데이터를 공개하거나 전달하지 않는다.

`CNNConvolutionLab`은 `Scripts/CNNConvolutionLab/ConvolutionCalculation.cs`의 `CreateExample()`에 저장된 0~3 값의 고정 5×5 RGB 배열로 시작한다. 순차 입장, 태블릿 직접 이동, 단독 실행 모두 같은 예제를 사용한다. 1-1의 선택 여부나 완료 상태로 입력을 바꾸지 않는다. 계산 결과는 이 배열과 필터로 매번 계산한다.

`FactorySceneLoadController`는 인접 씬을 미리 로드한다. ScreenLab과 ConvolutionLab은 로드 후 각자의 `Start`에서 자체 초기화하며, 공장의 현재 구역이나 실제 입장 여부를 전달받지 않는다. ConvolutionLab은 고정 예제를 준비하고 필터 배치 입력을 기다린다. 공장 내 로드와 단독 실행은 같은 시작 경로를 사용한다. 로드된 상태에서는 구역 이동만으로 체험을 중단하거나 초기화하지 않는다.

`LearningSessionManager`는 구체 체험 Manager를 참조하지 않고 `ILearningExperience`로 단계·진행률·출구 허용 상태를 조회하고 변경 이벤트를 구독한다. 언로드 전에는 같은 인터페이스의 `EndSession`으로 정리를 요청한다. 공장 셔터의 개방 조건은 [Factory Environment](factory-environment.md)의 셔터 동작을 따른다.

두 체험의 UI 버튼은 공용 `XRPlayerRig`에 구성한 EventSystem·XRUIInputModule을 사용한다. `ScreenLabUIController`와 `CNNConvolutionLabManager`는 입력 환경을 생성하거나 해제하지 않으며, 버튼의 기존 On Click 연결로 각 체험의 요청을 처리한다. 체험 종료·언로드 시 공용 입력 환경은 유지된다. ScreenLab 단독 실행은 씬에 배치된 공용 리그를 사용하고, 자체 리그가 없는 ConvolutionLab의 XR 조작은 공장에 로드된 공용 리그를 사용한다.

## ROOM #1-1 픽셀 큐브 미리보기

`Floating image board/Low resolution image`의 `PixelGridData`는 색점판 원본을 칸별 면적 평균으로 48×27 RGB 배열에 저장한다. `GetColor(x, y)`와 `TryWorldToGrid`는 왼쪽 아래 칸을 (0, 0)으로 사용한다. 원본 텍스처의 Read/Write가 필요하다.

같은 오브젝트의 `PixelShatter`는 단위 Cube 메시와 `PixelGridCubes` 재질을 사용한다. 기본 상태는 숨김이다. Inspector 컴포넌트 메뉴의 `ShowGrid`와 `HideGrid`로 전환한다. 표시 중에만 원본 렌더러를 가리고, 숨길 때 기존 상태로 복구한다. 큐브는 최대 250개씩 인스턴싱해 그린다. Play 중에는 돋보기의 기존 `SelectionChanged`가 처음으로 유효한 3×3 선택을 알릴 때 0.3초 이미지 페이드와 1초 큐브 전개를 시작한다. 기존 선택 중심을 48×27 좌표로 변환해 해당 3×3을 강조한다. RGB 확대도 같은 중심의 9개 색을 `PixelGridData.GetColor()`로 읽어 채널 표시와 숫자판에 전달한다. 확대를 시작할 때 9개 좌표와 RGB를 Console에 한 번 기록한다. 다시 놓으면 강조 위치만 갱신한다. 첫 `NextRequested`로 픽셀 2/2에 들어가면 선택된 3×3을 제외한 큐브가 현재 위치에서 1초 동안 이미지 면으로 돌아간다. 이미지가 다시 나타나면 큐브 그리기를 중단하고 3×3 외곽선만 남긴다. RGB 펼침 시작과 ‘처음으로’는 기존 이벤트를 통해 연출을 중단하고 원본 렌더러 상태를 복구한다.

## ROOM #1-1 돋보기 전시대

`CNNScreenLab` 씬의 `CNN Screen Lab/MagnifierPedestal` Transform이 전시대 위치를 정한다. 받침대 윗면은 지름 0.56m, 바닥 기준 높이 1.0m에 있고 `MagnifierDock`은 윗면에서 0.175m 위에 있다. 시작하거나 선택을 초기화하면 돋보기는 이 기준점으로 돌아온다. 전시대에는 충돌 영역을 두지 않으며 기존 파란 바닥 표시는 비활성 상태로 보존한다.

전시대 위 돋보기의 `MagnifierIdleFloat`는 초당 30° 회전하고 0.5Hz로 ±3cm 움직인다. 기존 `XRGrabInteractable.selectEntered`에서 멈추고 ‘처음으로’의 `ScreenLabUIController.ResetRequested`에서 다시 시작한다. 잡힌 상태의 리셋 요청은 기존 동작과 같이 무시한다.

돋보기에는 짙은 금속 테두리와 반투명 렌즈가 있다. 같은 잡기 이벤트에서 `MagnifierPickupFX`가 렌즈 가장자리의 하늘색 띠를 먼저 반짝인다. 0.14초 뒤에 빛기둥이 0.4초에 걸쳐 꺼지기 시작하고, 전시대 링은 기존 밝기의 22%로 낮아진다. 돋보기 위치에서 최대 0.5초 동안 하늘색 파티클을 표시한다. Inspector의 `pickupClip`에 클립을 연결하면 공간 효과음을 재생한다. ‘처음으로’는 조명을 복구하고 다음 첫 잡기 연출을 준비한다.

## 공중 합성곱 구성

`ConvolutionWorkbench.prefab`의 가운데에는 중간 계산판과 최종 출력판을 정면으로 나란히 둔다. 왼쪽 입력판과 필터 시작 위치는 -40°, 오른쪽 안내판은 +40°로 돌렸다. 작업대는 넓은 직선 상판과 좌우 40° 날개 상판으로 이어진다. 목표·조작 안내판은 오른쪽 날개 상판의 중앙에 두고, 왼쪽 상판은 펼쳐진 입력 프레임과 필터 시작 위치 아래까지 닿는다. 공장 콘텐츠 기준점은 `(-28.55, -0.3, -2.0)`, Y 회전은 -90°, 콘텐츠 배율은 1.2, 내부 Workbench 배율은 1.15다.

`WorkbenchHologramBackdrop`이 작업대와 표시판 뒤에 넓어진 곡면 홀로그램 배경을 그린다. 배경은 서쪽 공장 벽과 주변 가구 사이에 간격을 두고 배치한다.

| 공간 요소 | 현재 표시 |
| --- | --- |
| 입력 | 5×5 RGB 세 층. 뒤 채널은 앞 채널에 비해 로컬 X -0.34, Y +0.06, Z +0.30씩 어긋난다. |
| 비활성 채널 | 외곽 프레임·측면 채널 라벨·현재 3×3 영역은 남기고, 상단 제목과 숫자 타일은 숨긴다. 비활성 내부 격자선은 만들지 않아 뒤 채널 숫자를 가로지르지 않는다. |
| 필터 | 손잡이 하나와 연결된 RGB 세 프레임. 활성 채널의 가중치 숫자만 표시한다. 세 프레임은 하나의 잡기 대상으로 함께 움직인다. |
| 중간 계산 | 입력 오른쪽 앞의 별도 3×3 격자에 현재 채널의 아홉 곱을 표시한다. 최종 출력과 셀을 공유하지 않는다. |
| 최종 출력 | 더 오른쪽의 전용 3×3 격자. 계산 위치에 해당하는 출력만 기록하고 중간 곱으로 덮어쓰지 않는다. |
| 연산식 | 곱셈식과 채널·RGB 합산식은 중간 계산판 아래에 표시한다. 숫자 사본만 이동하고 원본 입력은 보존한다. |
| 단계 안내 | 상단의 어두운 설명판에 현재 제목과 짧은 설명을 표시한다. |
| 조작 | 오른쪽 세로 안내판에 목표, 현재 단계 조작법, 주 동작·다시 보기·일시정지·처음으로 버튼을 배치한다. |
| RGB 상태 | 상단 설명판의 가로 카드에 채널별 대기·진행 중·완료 합을 표시한다. |

배치 단계의 손잡이 안내는 필터 근처에, 곱셈·합산식은 계산 대상 근처에 표시한다. `PixelCalculationUI.prefab`에 상단 설명판과 오른쪽 안내판의 배치가 저장되어 있다. 버튼은 공용 `WorldUIButton`의 중첩 인스턴스다.

오른쪽의 주 동작 위치에 필터 자동 배치, 다음 단계, 한 칸 자동 이동, 결과 확인, 체험 마치기를 단계에 따라 표시한다. 현재 사용할 수 있는 주 동작 버튼의 금색 테두리는 밝아졌다 어두워진다. 일시정지 중에는 체험 재개 버튼을 강조한다. 다시 보기는 별도 줄에 있다. 재생 중에는 다음·다시 보기 버튼을 숨긴다. 일시정지는 연출 시간·필터 입력·퀴즈·다음·다시 보기·자동 배치를 멈춘다. 처음으로는 현재 코루틴과 입력을 정리하고 첫 배치로 돌아간다.

## 계산 규칙

입력 5×5×3, 공간 필터 3×3, 전체 가중치 3×3×3, stride 1, 패딩 없음, 편향 0이다. 세 채널의 연습용 가중치는 모두 `1 0 0 / 0 1 0 / 0 0 1`이다. 입력값과 가중치는 기존 고정 예제를 유지한다. 각 채널의 아홉 곱을 더하고 RGB 채널 합 세 개를 더해 출력 한 칸을 만든다. 짧은 합산식에서는 가중치 0 항을 생략하지만 중간 계산판에는 0인 곱도 표시한다.

필터 왼쪽 위 `(row,column)`은 출력판의 같은 좌표에 대응한다. 필터의 세 층과 입력의 세 영역은 같은 공간 좌표 이동을 공유한다. `ConvolutionCalculation.ForWindow`는 입력 배열을 공유하는 새 읽기 전용 위치 객체를 반환한다. 입력 배열을 변경하거나 외부에 공개하지 않는다.

## 진행 순서

1. **배치:** R 숫자와 RGB 세 입력 프레임을 표시한다. 반투명 필터 이동 미리보기와 점선 목표를 따라 Grip으로 필터를 놓는다. 목표 로컬 반경 0.15 안에서 놓으면 정렬하고, 밖이면 시작 위치로 돌아간다. 자동 배치도 제공한다. 내부 배율을 포함한 현재 반경은 약 0.207m다.
2. **곱하기:** 첫 R에서 필터의 아홉 칸을 왼쪽 위부터 행 순서로 상세히 재생한다. 각 칸의 입력값과 가중치를 곱한 뒤 결과를 중간 계산판의 대응 칸으로 하나씩 옮긴다. 출력판은 아직 비어 있다. 아홉 칸이 채워지면 `다음 · 아홉 곱 더하기` 또는 `다시 보기`를 기다린다.
3. **채널 합:** 아홉 곱의 사본이 중간 계산판 중심에 모이고 R 합이 된다. 원래 곱은 유지한다. `다음 · RGB 합치기` 또는 현재 합산 단계의 `다시 보기`를 기다린다.
4. **RGB와 첫 출력:** 같은 위치에서 G·B의 곱과 채널 합을 표시한다. R·G·B 합 숫자가 각 필터 층에서 합산 지점으로 모이고, 하나의 출력값이 오른쪽 전용 출력판에 기록된다. `다음 · 필터 한 칸 이동` 또는 이 RGB 합산 단계의 `다시 보기`를 기다린다. 재보기는 해당 단계만 재생하며 진행률을 중복 가산하지 않는다.
5. **직접 한 칸 이동:** 손잡이를 다시 잡고 오른쪽 목표로 옮긴다. 손의 이동을 시작점~다음 격자 중심 선분에 투영하므로 높이·깊이는 고정되고 한 칸 범위를 벗어나지 않는다. 목표 로컬 거리 0.07 안에서 놓으면 정렬한다. 미달하면 시작점으로 돌아가 안내한다. `한 칸 자동 이동`은 같은 목표로 이동하며 퀴즈를 건너뛰지 않는다. 잡은 상태에서 일시정지하면 잡기를 해제하고 이동 시작점으로 돌아간다.
6. **위치 퀴즈:** 출력판 빈칸 8개 중 하나를 XR 레이로 선택한다. 순환 강조는 약 0.30초 간격이다. 오답이면 선택한 행·열과 “오른쪽 한 칸” 힌트를 표시하고 재선택을 기다린다. 정답인 1행 2열을 선택하면 입력을 닫고 계산을 진행한다.
7. **자동 계산:** 나머지 위치에서 이동 → R → G → B → RGB 합 → 출력 기록을 진행한다. 왼쪽부터 오른쪽, 위에서 아래의 행 순서다. 다음 행의 시작으로 이동할 때는 별도 안내를 표시한다. 자동 계산은 첫 상세 연출에 적용하는 공통 배속에 1.5배를 더 곱하며 일시정지할 수 있다.
8. **결과 확인:** 아홉 출력에서 95%가 되고 `결과 확인`을 기다린다. 확인 후 중간 곱 판을 숨기고 입력·필터·완성된 출력은 남긴다. 첫 입력 영역과 출력 1행 1열을 강조하며 첫 RGB 합산식을 표시한다. 별도의 복제 출력 요약판은 사용하지 않는다. `체험 마치기`를 눌러야 100% 및 출구 허용 상태가 된다.

출력 순서는 `(1,1)→(1,2)→(1,3)→(2,1)→(2,2)→(2,3)→(3,1)→(3,2)→(3,3)`이다. `LessonPlayback`의 공통 배속은 1.5배다. 첫 R의 상세 곱셈 연출은 약 11.5초이며, 자동 이동은 일반 한 칸이 약 0.13초, 다음 행 시작으로 돌아갈 때 약 0.29초다. 다음·다시 보기, 배치, 직접 이동, 퀴즈, 결과 확인과 종료는 사용자 입력을 기다린다.

```text
1 0 1 3 0          2 3 0 2 1          2 0 3 1 0

첫 R 곱            최종 출력
0 0 0              15 13 18
0 2 0              10 18 12
0 0 1              15 13 12
```

첫 RGB 식은 `R 3 + G 6 + B 6 = 15`, 다음 위치는 `R 6 + G 4 + B 3 = 13`이다. 출력값은 하드코딩하지 않고 고정 입력과 가중치로 계산한다.

## 중단·재시작과 확인 범위

Manager는 먼저 소유 코루틴을 중단하고 단계 Controller의 `Cancel`로 다음·재보기·배치·이동·퀴즈 입력 구독을 해제한다. 숫자 사본, RGB 합 사본, 잡기, 강조와 숨겨진 합계 글자를 정리한다. 직접 이동을 취소할 때 XR의 자유 위치 추적 설정을 복원한다. 다시 시작하면 새 계산 객체, 빈 두 격자와 RGB 카드로 첫 배치를 시작한다. 내부 XR 리스너는 표시 생성부터 폐기까지 유지하고 폐기 시 해제한다.

2026-11-11~12 Unity 6000.3.24f1에서 컴파일과 공장 씬 Play 검증을 수행했다. XR 레이의 자세와 누름·해제를 주입해 첫 배치의 목표 밖 복귀·목표 정렬, 자동 배치, 단계별 다음·다시 보기, 직접 한 칸 이동의 축 제한·미달 복귀·목표 정렬, 퀴즈 오답·정답, 계산 중 일시정지·재개, 아홉 출력값, 결과 확인과 종료, 재시작 시 계산판·진행률·출구·잡기 설정 초기화를 확인했다. 출력은 위 고정 예제와 일치하며, 결과 확인 단계는 95%·출구 불가, 종료 후에는 100%·출구 허용이다. 화면 확인에서 드러난 원거리 도착점과 비활성 내부 격자선의 숫자 가림을 수정했고 수정본 재컴파일도 통과했다. 실제 HMD의 양안 시야와 물리 컨트롤러 조작은 별도 확인이 필요하다. 테스트 파일·프로젝트 복사본·플레이어 빌드는 생성하지 않았다.
